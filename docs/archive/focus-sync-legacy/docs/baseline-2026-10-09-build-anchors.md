## 2. ⚠️ 后台程序的指纹不能当锚点 —— Rust 构建不是字节可复现的

**实测结论(2026-10-09 搬迁期间发现):**

同源码、同编译器(Rust 1.90)、同机器,**只换输出目录**,两次构建的二进制指纹就不同:

| 构建 | 指纹 |
|---|---|
| 仓内输出目录 | `86BE0DF1F28A5ECA…` |
| 换到 `C:\Temp` 输出目录 | `9A8C4040E11E2F03…` |

再叠加 Rust 版本差异与源码路径迁移,历史上已出现过至少 4 个不同的指纹:

| 来源 | 指纹 |
|---|---|
| 1.85 / 主仓旧路径 | `30166457D37FF34A…` |
| 1.90 / `C:\Temp` 探针 | `5B234F286AFFC9C7…` |
| 1.90 / 品牌仓新路径 | `86BE0DF1F28A5ECA…` |

⇒ **「同样的原料造出同样的东西」只在插件载荷上成立,后台程序只保证功能等价。**

| 载荷 | 能否作 sha 锚点 | 判据 |
|---|---|---|
| 插件主文件 `dist/index.js` | ✅ **可以** | sha `ECED2EBE4D1598BA…` |
| 安装配置 `package.json` | ✅ **可以** | sha `9F34E0D2FAAC757C…` |
| 语言包 `locales/*.json` | ✅ **可以** | 手工维护,无构建 |
| 后台程序 `spike.exe` | ❌ **不可以** | 只验「通过 73 个测试」 |

**任何拿后台程序 sha 做回归判断的检查都是无效的** —— 它会随机失败,而失败时
东西其实没坏。这类门禁比没有更糟:它训练你忽略门禁。

## 5. ⚠️ 两个互操作常量:计划文档的路径是错的

计划 §3.2 写的路径**少了一层目录**。按它去找会扑空:

| 常量 | 计划文档写的 | **实际位置** |
|---|---|---|
| `MDNS_INSTANCE_NAME` | `src/lan_share/types.rs:15` | **`src-tauri/src/lan_share/types.rs:15`** |
| `LEGACY_DEFAULT_FILE_MANAGER_DATA_DIR_NAME` | `src/windows_installation.rs:30` | **`src-tauri/src/windows_installation.rs:30`** |

行号是对的,路径缺 `src-tauri/` 前缀。两个常量当前值均为 `"Sigma File Manager"`。

**改名(P4)时禁止全局替换 `Sigma File Manager`** —— 全局替换会同时改掉这两个,
而部署 sha 门禁**照样 PASS**(它只比对已安装文件,不看源码常量),
后果是 LAN 共享与默认文件管理器接管**静默失效**。
