## 二、2026-10-10 刚做完的事

一天内完成了两件独立的事，均已上线。

### A. 更新渠道从 GitHub 迁到自建站

原因：国内访问 GitHub 困难。

- 站点目录 `alpha-file-manager/` 已建好并上传（nginx，`.htaccess` 无效，别指望它）
- 应用查站点 `version.json` 判断更新；**仅当主源请求失败**才回落 GitHub。
  主源「解析成功但无更新」时**不查兜底源**（有单测 `does_not_query_fallback_when_manifest_says_up_to_date` 锁死），
  否则「改回 version.json 即停止推送」这个最廉价的回滚手段会失效
- 下载后本地校验 sha256，不匹配即**删除文件**
- 不引入 minisign，用 sha256

### B. 安装器三个故障的根因修复（详见 `docs/handoff-2026-10-10-installer-instdir-rootcause.md`）

用户报的「开始菜单快捷方式消失 / 路径少冒号 / 勾选运行无反应」**同源**：
Tauri 把 `InstallLocation` 存成带引号字符串，旧钩子 `StrCpy $INSTDIR "$0"` 形成双重引号，
NSIS 分词吃掉盘符冒号 → 路径被当成相对系统目录 → 重写成 `C:\D\...`。

一并修掉的：

- 新增 `AlphaNormalizeInstDir` 归一化闸门（去引号、修冒号、校验 `X:\`），已损坏的机器会**自愈**
- 钩子确定 `$INSTDIR` 后重新 `SetOutPath "$INSTDIR"`（否则主 exe 与资源静默写偏）
- POSTINSTALL 用不带引号的值回写 `InstallLocation`
- 删除全局 `taskkill msedgewebview2.exe / crashpad_handler.exe`（实测会误杀 Edge 等其他应用）
- release 版启用 `tauri-plugin-log`（原先被 `cfg!(debug_assertions)` 包住，出货版零日志）

## 四、环境：坏掉的工具链与可用替代

**这台机器上有三处环境损坏。动手前先知道绕法，否则会浪费大量时间。**

### 4.1 Rust stable toolchain 损坏

`rustup` 的代理 shim 从 `C:\Users\Duanyi\.cargo\bin` 消失，
且 `stable`(1.97.1) 的标准库只剩元数据存根：

```
only metadata stub found for rlib dependency rustc_std_workspace_core
```

**可用替代**（`Cargo.toml` 要求 `rust-version = 1.88.0`，1.90.0 满足）：

```powershell
$tc = 'C:\Users\Duanyi\.rustup\toolchains\1.90.0-x86_64-pc-windows-msvc\bin'
[Environment]::SetEnvironmentVariable('PATH', "$tc;$env:PATH", 'Process')
Set-Location 'F:\soft\00selfmade\filemanager\sigma-file-manager\src-tauri'
& "$tc\cargo.exe" check --lib
```

**PATH 注入必须用 `[Environment]::SetEnvironmentVariable(..., 'Process')`**，
不要用 `$env:PATH`。这是绕过不是修复，建议尽快 `rustup toolchain install stable` 重装。

> 另注：Rust 构建**非字节可复现**（同源码只换 `CARGO_TARGET_DIR` 二进制 sha 就变）。
> 判断 Rust 产物「有没有变」**一律不要比对 sha**，改用「测试是否仍全绿」+「包内载荷与源文件逐字节一致」。

### 4.2 Python 环境大面积损坏

系统 Python 抽样 15 个包有 13 个真坏（`source code string cannot contain null bytes` /
`bad marshal data`），影响 python-pptx / xlrd / docx 等。

**但发布通道不受影响** —— SFTP 走独立 venv，状态良好：

```
E:\办公文件\L1网站\.venv-sftp\Scripts\python.exe   → paramiko 5.0.0 ✅
```

### 4.3 PowerShell 5.1 执行的中文脚本必须带 UTF-8 BOM

无 BOM 的 `.ps1` 按 GBK 解析，中文乱码里的引号会破坏语法，
**报错行号还和真实问题对不上**。写完先自检：

```powershell
$err = $null
[void][System.Management.Automation.Language.Parser]::ParseFile($f, [ref]$null, [ref]$err)
```

## 六、常用命令

### 构建与发布（一整套，顺序不能乱）

```powershell
# 1. 写更新说明（纯文本，脚本会自动追加版本号/大小/sha256）
#    建议放 _notes.md，不要手写构建信息

# 2. 升版本 + 构建 + 复制到站点源 + 写 version.json  （约 8 分钟）
npm run release:prepare -- --bump patch --notes-file ./_notes.md
#    只想重打不升版本： --bump none
#    不想重新构建：     --skip-build

# 3. 上传站点并回读校验
npm run release:upload

# 4. GitHub 兜底 release
node scripts/release-publish.mjs prepare --write-notes ./_notes.md   # 生成带构建信息的说明
npm run release:github

# 5. 公网回读
npm run release:verify
npm run release:status
```

## 八、工作方式约定

- **面向用户的输出一律简体中文**（含代码注释里给人看的部分）。
- **不要在用户重启应用/服务的窗口期部署。**
- **验证必须测被测对象真实走的那条链路**；判别性结论要带对照组，
  不能拿「编译通过 / 退出码 0」当验证。
- 门禁要长在部署路径上，不能是旁边的可选步骤。
- 抓不到二进制、拆不动包、读不了源码时，**如实说「不可知」，不要写成「已排除」**。
