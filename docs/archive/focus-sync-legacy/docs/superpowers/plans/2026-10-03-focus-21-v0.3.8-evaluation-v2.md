## 1. 评估:Mavis 第 10 轮 5 项新发现

### 1.1 🟡 A4 [MEDIUM] — helper 只查 1001,漏掉 1148

**问题分析**:
- 当前 helper `find_automation_id_edit("1001")` 只查 1001
- 但 `filename_edit_score`(uia_inject.rs L533-548)**早就识别 1148 = Modern IFileDialog combo**(score=100,比 1001=90 高)
- 实际场景:
  - Win 7/8 Modern IFileDialog(Vista+):可能只有 1148
  - Win 11 某些 app:可能 1148 而不是 1001
  - Edge WinUI 3 Modern Save As(用户截图):目前是 1001
  - Edge Legacy:COM SetFolder 路径,不走 UIA

**修复方案**:
```rust
// A4: helper 接受 1001+1148 双 aid
fn find_ifiledialog_edit(elements: &IUIAutomationElementArray) -> Option<IUIAutomationElement> {
    const IFDIALOG_EDIT_AIDS: &[&str] = &["1001", "1148"];
    for target_aid in IFDIALOG_EDIT_AIDS {
        if let Some(elem) = find_automation_id_edit(elements, target_aid) {
            return Some(elem);
        }
    }
    None
}
```

**判断**:**采纳**。Modern IFileDialog combo 漏处理会让某些 app 不 work,5 min 修复必做。

### 1.2 🟢 A5 [LOW] — 现有 best_edit 系统已隐含 1001 选择

**问题分析**:
- 现有 inventory 循环 + `filename_edit_score` 已经选 1001(可能 1148)
- v0.3.6 L2-1 不是"漏看 1001",而是"看到 1001 但判定为 WinUI 3 跳过"
- v0.3.8 helper 双重查找是安全的(防止 inventory 漏识别变种),但 inventory 系统已做这件事

**判断**:**不动**(LOW 风险,refactor 可选)。v0.3.8 helper 保留(`find_automation_id_edit` 比 `best_edit` 更精确,限定 ControlType)。

### 1.3 🟡 A6 [MEDIUM] — read back verify 应当容忍子集

**问题分析**:
- 当前 v0.3.8 `if readback_str != target_path` 严格相等
- 实际场景:某些 dialog 在 SetValue 时规范化 path
  - `C:\downloads\` → `C:\downloads`(去 trailing slash)
  - `C:\downloads\` → `C:\downloads\untitled.txt`(加默认 filename)
- 严格相等会误判 verify FAILED → 返回 Unsupported → 用户看不到 sync work

**修复方案**:
```rust
// A6: 容忍子集匹配
fn path_matches(readback: &str, target: &str) -> bool {
    let readback_normalized = readback.replace('/', "\\");
    let target_normalized = target.replace('/', "\\");
    
    if readback_normalized == target_normalized { return true; }
    if readback_normalized.starts_with(&target_normalized) { return true; }
    if target_normalized.starts_with(&readback_normalized) { return true; }
    
    false
}

// 在 Fix-A 里替换 if readback_str != target_path:
if !path_matches(&readback_str, target_path) {
    warn!("v0.3.8: SetValue verification FAILED ... readback='{}' target='{}'",
          readback_str, target_path);
    state.inc_unsupported_dialog();
    return Ok(DialogOutcome::Unsupported);
}
```

**判断**:**采纳**。5 min 修复避免 path 规范化误判。

### 1.4 🟢 A7 [LOW] — best_button 可能误判 Cancel

**问题分析**:
- `confirm_button_score` 选 `automation_id='1'` = IDOK = Save(典型)
- 罕见情况下 `id='1'` 可能是 Cancel(Win32 标准 IDOK=1=Save,但非 MS app 可能违反)
- 风险:Invoke Cancel 关闭 dialog 但不保存

**修复方案**:
```rust
// A7: 验证 best_button 是 Save 不是 Cancel
fn verify_best_button_is_save(button: &IUIAutomationElement) -> bool {
    let name = current_name(button).to_lowercase();
    let is_save = name.contains("保存") || name.contains("save")
        || name.contains("open") || name.contains("打开")
        || name.contains("ok") || name.contains("确定");
    if !is_save {
        warn!("v0.3.8: best_button name='{}' is not Save; skipping commit Invoke", name);
    }
    is_save
}
```

**判断**:**采纳**。5 min 修复防止误 Invoke Cancel。

### 1.5 🟡 A8 [MEDIUM] — fallback B 改用 Invoke button

**问题分析**:
- 当前 v0.3.8 fallback B 用 `commit_via_fallback_enter`(SendMessageW Enter)
- WinUI 3 wrapper 可能屏蔽 SendMessageW Enter 到 inner Edit
- 实际:WinUI 3 接受 UIA SetValue,但 Win32 message 路由被 wrapper 拦截

**修复方案**:
```rust
// A8: fallback B 优先 Invoke button
fn fallback_b_force_commit(
    best_button: Option<&IUIAutomationElement>,
    edit_1001: &IUIAutomationElement,
) -> bool {
    if let Some(button) = best_button {
        if verify_best_button_is_save(button) {
            match unsafe {
                let invoke: IUIAutomationInvokePattern =
                    button.GetCurrentPatternAs(UIA_InvokePatternId)?;
                invoke.Invoke()
            } {
                Ok(_) => {
                    info!("fallback B: Invoke Save button succeeded");
                    return true;
                }
                Err(e) => warn!("fallback B: Invoke Save button failed: {e}"),
            }
        }
    }
    
    // 次选:SendMessageW Enter(WinUI 3 可能屏蔽)
    commit_via_fallback_enter(edit_1001);
    false
}
```

**判断**:**采纳**。5 min 改进让 fallback B 更鲁棒。

## 2. 🔴 A9 [HIGH] — 关键 UX 倒退警告评估

### 2.1 论证回顾(我之前完全错)

**focus-18 v0.3.1 working path**:
1. 1001 SetValue → filename 框被改(**中间态**)
2. **Auto-Confirm ON**(`should_commit=true`)→ Invoke Save
3. dialog **立即自动关闭** → 用户**看不到中间态** → ✅ 接受

**v0.3.8(我设的 default false)**:
1. 1001 SetValue → filename 框被改(**中间态**)
2. **Auto-Confirm OFF**(`should_commit=false`)→ **不 Invoke**
3. dialog **不自动关闭** → 用户**看到中间态** → "filename 被改" → ❌ reject(回到 focus-19/20 痛点)

### 2.2 我之前的错误认识

❌ **"默认 should_commit=false 是安全默认"** — 错
- focus-18 working path 已经证明:`should_commit=true` 才是 working
- "安全默认"反而让 dialog 不动,用户无法看到 sync 效果
- 用户核心诉求是"dialog 真正跳转",**Auto-Commit 是核心机制**

❌ **"沿用 focus-18 默认"** — 错
- focus-18 v0.3.1 没有"默认 ON/OFF",是**Auto-Confirm 工具栏 toggle** 控制
- 我把 focus-18 的"Auto-Confirm OFF"作为 v0.3.8 默认,**丢失了 focus-18 working 的核心**

### 2.3 修复方案(采纳 A9)

**writer.rs::write_path L43-48**:
```rust
// 当前(v0.3.5/6/7):
let should_commit = if auto_confirm {
    state.try_mark_committed(hwnd_u32)
} else {
    false       // ← 错
};

// v0.3.8(采纳 A9):
let should_commit = true;   // ← 总是 commit(沿用 focus-18 working path)
```

**等等**:`should_commit=true` 是否对所有 dialog 都安全?
- 41477 分支(Chromium):SetValue + Invoke → dialog 关闭(用户预期)
- 1001/1148 分支(WinUI 3 wrapped):SetValue + Invoke Save → dialog 关闭(用户预期)
- Edge Legacy(启用 flag):COM SetFolder(不走 should_commit)
- 真 WinUI 3(无 1001/1148/41477):返回 Unsupported,不动 dialog
- Photos / Notepad:user 已 OK,Auto-Commit 让 dialog 关闭 → ✅

**结论**:`should_commit=true` 默认对所有路径都安全,符合 focus-18 working。

### 2.4 toolbar 文案(A3 改进)反映 A9

当前 A3 文案(v0.3.8 plan):
```js
'Auto-Confirm: ' + (autoConfirm
    ? 'ON (Save button auto-clicked after sync)'
    : 'OFF (filename written, you click Save manually)')
```

**问题**:如果 A9 改默认 `should_commit=true`,toolbar 描述仍说 "OFF 时 user 手动 Save" 是错的 — **实际是 OFF 时也 Auto-Commit**。

**修复 A3 + A9 文案**:
```js
'Auto-Sync: ' + (autoSync
    ? 'ON (filename written + auto Save)'
    : 'OFF (filename written, you click Save manually)')
```

**或保持 `should_commit=true` 默认,toolbar 改名**:
- toolbar toggle 不再是 "Auto-Confirm" 而是 "Manual Save"(rare case)
- 工具栏 ON = 强制手动 Save(罕见)
- 工具栏 OFF = 默认 Auto-Commit(95% 场景)

**或简单保留 toolbar 名字 + A3 文案 + A9 改默认**:
- 默认 should_commit=true(A9 改)
- toolbar 仍是 "Auto-Confirm" toggle(控制 commit 行为)
- 文案:用户可切换"自动 Save vs 手动 Save"
