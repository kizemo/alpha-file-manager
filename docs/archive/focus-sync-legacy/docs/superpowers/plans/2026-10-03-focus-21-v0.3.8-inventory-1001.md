### 1.3 关键观察(Phase 1 真正的根因)

**🎯 关键 inventory 行**:

| 控件 | ControlType | automation_id | name | value |
|---|---|---|---|---|
| A | 50003 (Pane) | **`FileNameControlHost`** | 文件名: | (空) |
| B | 50004 (Edit) | **`1001`** ← **关键** | 文件名: | `WeavePage_3.0.0_x64-setup.exe` |
| C | 50000 (Button) | `1` | 保存(S) | (空) |
| D | 50000 (Button) | `2` | 取消 | (空) |

**分析**:

1. **`automation_id='1001'` 存在** — 这是 **legacy IFileDialog filename Edit 的标准 AutomationId**(沿用 Win32 dialog convention)
2. **`automation_id='FileNameControlHost'`** — WinUI 3 的 host wrapper (Pane)
3. **ControlType=50004 (Edit)** — 是 Edit 控件,可 SetValue
4. **value 已经是 `WeavePage_3.0.0_x64-setup.exe`** — 当前文件名,不是路径

**v0.3.6 L2-1 的判定逻辑错在哪里**:

```rust
if let Some(ref edit) = best_edit {     // ← best_edit 是 highest-score Edit
    warn!("v0.3.6: WinUI Save As detected (no 41477, no SetFolder, has Edit element). ...");
    state.inc_unsupported_dialog();
    return Ok(DialogOutcome::Unsupported);
}
```

**判定 "WinUI Save As" 的依据**:
- ❌ `no 41477` — 对,Chromium Save As 的 address bar 没有
- ❌ `no SetFolder` — 对,COM AccessibleObjectFromWindow 失败
- ✅ `has Edit element` — 对,1001 存在

**但 v0.3.6 缺一个判定**:**`has automation_id 1001` (IFileDialog 兼容) ≠ WinUI 3 真正的 inner 没有 IFileDialog 兼容**。

**真正的 WinUI 3 vs WinUI 3-wrapped-IFileDialog 区别**:

| dialog 类型 | Outer | 1001 (IFileDialog Edit) | 41477 (Chromium address bar) | SetFolder COM |
|---|---|---|---|---|
| **Win 11 Photos** | WinUI 3 包裹 | ✅ 存在 | ❌ | ❌ (outer 无 IAccessible) |
| **Edge WinUI 3 Modern Save As** | WinUI 3 包裹 | ✅ 存在 | ❌ | ❌ (outer 无 IAccessible) |
| **Edge Legacy (IFileDialog)** | Win32 #32770 | ✅ 存在 | ❌ | ✅ (outer 是 IAccessible) |
| **Chromium Save As** | Win32 | ❌ | ✅ | ❌ |
| **Notepad Save As** | Win32 #32770 | ✅ 存在 | ❌ | ✅ |
| **影刀 Save As** | Win32 #32770 | ✅ 存在 | ❌ | ✅ |

**关键洞察**:**WinUI 3 Modern Save As dialog 内嵌了 legacy IFileDialog**(1001 存在),只是 outer 是 WinUI 3 wrapper 不支持 IAccessible。所以 COM SetFolder 失败,但 **UIA SetValue 到 1001 应该 work**。

**focus-19 v0.3.2 错误地"返回 Unsupported 不写",6 轮修复都没看 inventory log 里的 `automation_id='1001'`**。

            edit.GetCurrentPatternAs(UIA_ValuePatternId)?;

**需要新增 helper (Mavis A1 改进 — 限定 ControlType = Edit)**:
```rust
/// v0.3.8 (Mavis A1 [HIGH]): find_automation_id_edit — find element by
/// automation_id AND verify it is an Edit ControlType.
///
/// Some dialogs may have multiple elements with the same automation_id
/// (e.g., automation_id='1001' could appear on both Pane 50003
/// FileNameControlHost and Edit 50004 the actual filename control).
/// Without ControlType filtering, SetValue would fail on the Pane
/// ("Element does not support ValuePattern").
///
/// This helper matches BOTH conditions to avoid silent UIA errors.
fn find_automation_id_edit(
    elements: &IUIAutomationElementArray,
    target_aid: &str,
) -> Option<IUIAutomationElement> {
    let count = unsafe { elements.Length() }.ok()?;
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        // Verify BOTH automation_id AND control_type match
        let aid = current_automation_id(&element);
        if aid != target_aid {
            continue;
        }
        let ct = unsafe { element.CurrentControlType().ok()? };
        if ct == UIA_EditControlTypeId {
            return Some(element);
        }
        // aid matched but control_type wrong — log + skip
        warn!(
            "v0.3.8: find_automation_id_edit: aid='{aid}' matched but \
             ControlType={ct:?} is not Edit; skipping"
        );
    }
    None
}
```
