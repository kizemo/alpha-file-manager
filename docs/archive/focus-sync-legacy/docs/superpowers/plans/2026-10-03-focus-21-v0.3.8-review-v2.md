### 2.3 🟡 A6 [MEDIUM] — read back verify 应当容忍子集匹配

#### 2.3.1 问题

**Claude v0.3.8 §4.1 L260-268**:
```rust
if readback_str != target_path {
    warn!("v0.3.8: SetValue verification FAILED ...");
    state.inc_unsupported_dialog();
    return Ok(DialogOutcome::Unsupported);
}
```

**问题**:`readback_str != target_path` 严格相等判断。

#### 2.3.2 实际场景

**某些 dialog 在 SetValue 时可能触发自动 navigation**(Edge legacy IFileDialog):
- user 输入 `C:\downloads\` → dialog 自动 navigation → 看左 visible 显示新路径
- 但 Edge 也可能规范化 path:`C:\downloads\` → `C:\downloads`(去 trailing slash)
- 或添加 filename 后缀:`C:\downloads\` → `C:\downloads\untitled.txt`(默认文件名)

**严格相等**会误判这些情况为 verify FAILED → 返回 Unsupported → 用户看不到 sync work。

#### 2.3.3 修复方案

```rust
// A6 [MEDIUM]: 容忍子集匹配
fn path_matches(readback: &str, target: &str) -> bool {
    let readback_normalized = readback.replace('/', "\\");
    let target_normalized = target.replace('/', "\\");
    
    // 严格相等
    if readback_normalized == target_normalized {
        return true;
    }
    
    // 子集:readback 以 target 开头(target 是 readback 的前缀)
    // 例:readback="C:\downloads\file.txt", target="C:\downloads"
    // 例:readback="C:\downloads", target="C:\downloads\"(去 trailing slash)
    if readback_normalized.starts_with(&target_normalized) {
        return true;
    }
    
    // 子集:target 以 readback 开头(target 包含 readback)
    // 例:readback="C:\downloads", target="C:\downloads\"
    // 例:readback="C:\downloads", target="C:\downloads\file.exe"
    if target_normalized.starts_with(&readback_normalized) {
        return true;
    }
    
    false
}

// 在 Fix-A 里替换 if readback_str != target_path:
if !path_matches(&readback_str, target_path) {
    warn!("v0.3.8: SetValue verification FAILED ... readback='{readback_str}' target='{target_path}'");
    state.inc_unsupported_dialog();
    return Ok(DialogOutcome::Unsupported);
}
```

**作用**:容忍 path 规范化(trailing slash)、filename 追加等合理变化,避免误判。

**风险**:
- 过宽容忍,可能接受真正失败的情况(例:readback 完全无关)
- **安全边界**:只容忍 readback/target 互相为前缀

**工作量**:5 min(加 helper + 改判断)

### 2.5 🟡 A8 [MEDIUM] — fallback B 的 Enter 实现有问题

#### 2.5.1 问题

**Claude v0.3.8 §5.3 L406**:
> 方案 B:1001 SetValue 但 SetValue 后立刻 Invoke Enter(commit_via_uia 第二个分支)— 强制 commit

**`commit_via_fallback_enter` 实际是**(uia_inject.rs L593-597):
```rust
fn commit_via_fallback_enter(edit: &IUIAutomationElement) {
    fallback_confirm(edit)
}

// L579-591:
fn fallback_confirm(edit: &IUIAutomationElement) {
    let native = unsafe { edit.CurrentNativeWindowHandle() }.unwrap_or_default();
    if native.is_invalid() {
        warn!("fallback confirm skipped: filename edit has no native window handle");
        return;
    }
    unsafe {
        let _ = SendMessageW(native, WM_KEYDOWN, Some(WPARAM(VK_RETURN)), Some(LPARAM(0)));
        let _ = SendMessageW(native, WM_KEYUP, Some(WPARAM(VK_RETURN)), Some(LPARAM(0)));
    }
}
```

**问题**:`SendMessageW(WM_KEYDOWN, VK_RETURN)` 到 filename edit native HWND。

**WinUI 3 wrapper 行为**:
- WinUI 3 包裹的 IFileDialog 接受 UIA SetValue(已验证 focus-18)
- 但 **WinUI 3 可能屏蔽 SendMessageW Enter 到 inner Edit**(UIA ValuePattern 接受 SetValue,但 Win32 message 路由被 wrapper 拦截)
- 实际:**SendMessageW Enter 到 WinUI 3 inner edit 可能不 work**

#### 2.5.2 改进方案

**fallback B 改为 commit_via_uia 的最佳方式**:

```rust
// W1 fallback 方案 B(改进): 1001 SetValue + Invoke Save button
fn fallback_b_force_commit(
    best_button: Option<&IUIAutomationElement>,
    target_path: &str,
    edit_1001: &IUIAutomationElement,
) -> bool {
    if let Some(button) = best_button {
        // 优先 Invoke Save button
        match unsafe {
            let invoke: IUIAutomationInvokePattern =
                button.GetCurrentPatternAs(UIA_InvokePatternId)?;
            invoke.Invoke()
        } {
            Ok(_) => {
                info!("fallback B: Invoke Save button succeeded");
                return true;
            }
            Err(e) => warn!("fallback B: Invoke Save button failed: {e}"),
        }
    }
    
    // 次优:commit_via_uia 的 Enter 分支(已存在,但 WinUI 3 可能屏蔽)
    if let Some(edit) = Some(edit_1001) {
        commit_via_fallback_enter(edit);
    }
    
    false
}
```

**改进点**:
- 优先 Invoke Save button(UIA InvokePattern,标准 API)
- Fallback 才用 SendMessageW Enter(可能 work 可能不 work)
- 注释明确说明 WinUI 3 wrapper 可能屏蔽

**工作量**:5 min(改 fallback 实施细节 + 注释)

## 3. 🔴 A9 [HIGH] UX 倒退警告 — 默认行为回到 focus-19 被 reject 的痛点

### 3.1 关键论证

**v0.3.8 默认行为**(Claude v0.3.8 §8 预测):
- "Edge Modern Save As(无 flag)" → "dialog filename 写入 path,**用户需手动点 Save**"

**这是 user 6 轮 reject 的核心痛点**:
- focus-18 v0.3.1:`SetValue` + `should_commit=true` (Auto-Confirm) → Invoke Save → dialog 自动关闭 ✅
- focus-19 v0.3.2:删 SetValue → "啥也没干" user reject
- focus-20 v0.3.3:恢复 SetValue 但 `should_commit=false` → 用户看到 "filename 被改了" reject
- focus-21 v0.3.4/5/6/7:多次尝试修复,均未达成
- **v0.3.8:又 SetValue + `should_commit=false` 默认 → 用户仍会 reject "filename 被改"**

### 3.2 focus-18 working path 与 v0.3.8 的本质区别

**focus-18 v0.3.1 working**:
1. 1001 SetValue → filename 框被改(中间态)
2. **Auto-Confirm ON**(should_commit=true) → Invoke Save
3. dialog 立即自动关闭 → **用户看不到中间态**

**v0.3.8**:
1. 1001 SetValue → filename 框被改(中间态)
2. **Auto-Confirm OFF**(should_commit=false) → 不 Invoke
3. dialog 不自动关闭 → **用户看到中间态** → "filename 被改"

**本质区别**:**focus-18 让用户看不到中间态,v0.3.8 让用户看到中间态**。

### 3.3 修复方案 — 3 个选项

#### 选项 1:默认 should_commit=true(强制 Auto-Commit)

```rust
// writer.rs L43-48 改:
let should_commit = if auto_confirm {
    state.try_mark_committed(hwnd_u32)
} else {
    false       // ← 默认 false
};

// 改为:
let should_commit = true;   // 总是 commit(沿用 focus-18 working path)
```

**优点**:
- 用户永远看不到"filename 被改"中间态
- 100% work path
- 简单,不需要 fallback

**缺点**:
- 违反"安全默认"原则(focus-18 默认 OFF)
- 用户失去"我要手动 Save"的选择权
- 可能误保存到错误路径(罕见)

#### 选项 2:should_commit=false 默认,但加强 UX 反馈

```js
// index.js A3 改进(更明确告知):
'Sync mode: ' + (autoConfirm
    ? 'AUTO-SAVE (filename written + Save button auto-clicked)'
    : 'WRITE-ONLY (filename written, you MUST click Save)')
```

**优点**:用户明确知道默认行为
**缺点**:仍是 focus-20 的"filename 被改" UX 问题

#### 选项 3:should_commit=false 默认,但加 confirm dialog

```js
// PUSH 完成后,弹一个 confirmation:
sigma.ui.showNotification({
    title: 'Focus Sync',
    description: 'Path written: ' + path + '\nClick Save in the dialog to save.',
    type: 'warning',
    duration: 10000,
});
```

**优点**:用户每次切路径都明确告知
**缺点**:notification 多,frequency-spam

### 3.4 Mavis 推荐 — 选项 1(默认 Auto-Commit)

**理由**:
- focus-18 working path 全靠 Auto-Commit
- 用户的核心诉求"dialog 真正跳转"= dialog 自动 Save 到新路径
- "filename 被改"的 UX 痛点根源是"用户看到中间态",Auto-Commit 让用户看不到中间态
- **接受"安全默认"原则的 trade-off**:
  - 损失:用户失去"先看再 Save"的控制感(对少数派)
  - 收益:100% dialog 自动跳转(对绝大多数用户)

**实施修改**:
- writer.rs L46 改为 `let should_commit = true;` 
- **或**:写一个新参数 `force_commit: bool`,在 http_server 接 PUSH 时默认 true
- toolbar 的 Auto-Confirm 仍保留(用户可关闭其他场景的 Auto-Commit,如 SetValue 后 Enter to filename)

### 3.5 user-verify 改进(对应 W1 fallback)

如果**坚持 should_commit=false 默认**(不推荐):
- U-V1a 必做(用户验证"filename 写入 + 手动 Save"是否接受)
- 如果 reject → 立即走 fallback A(回退 v0.3.6 L2-1,不写 filename)— **这是最安全的回退**

**如果选选项 1(推荐)**:
