## 3. v0.3.8 plan 3 处关键改进(Mavis 补充)

### 3.1 🔴 A1 [HIGH] — `find_automation_id` 必须限定 ControlType = Edit

#### 3.1.1 Claude 当前 plan 的 helper 代码

```rust
fn find_automation_id(
    elements: &IUIAutomationElementArray,
    target_aid: &str,
) -> Option<IUIAutomationElement> {
    let count = unsafe { elements.Length() }.ok()?;
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        let aid = current_automation_id(&element);
        if aid == target_aid {
            return Some(element);
        }
    }
    None
}
```

#### 3.1.2 问题

**Claude helper 只匹配 `automation_id`,不限定 ControlType**。

**实际 inventory**(用户截图):
- `automation_id='FileNameControlHost'` (Pane 50003) ← **不匹配 "1001",但示意:某些 automation_id 不是 Notion 是控件类型**
- `automation_id='1001'` (Edit 50004) ← 我们要的

**但**:**如果 dialog 有其他控件 `automation_id='1001'` 但不是 Edit**(例如某个 Pane 用 1001 作为内部 ID):
- Claude helper 会错误匹配这个 Pane
- `SetValue` 到 Pane 会失败(error:`Element does not support ValuePattern`)

**风险等级**:中(inventory 中 id=1001 大概率是 Edit,但不是 100% 保证)

#### 3.1.3 修复方案

```rust
fn find_automation_id_edit(
    elements: &IUIAutomationElementArray,
    target_aid: &str,
) -> Option<IUIAutomationElement> {
    let count = unsafe { elements.Length() }.ok()?;
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        // Verify BOTH automation_id AND control_type match
        let aid = current_automation_id(&element);
        if aid != target_aid {
            continue;
        }
        let ct = unsafe { element.CurrentControlType().ok()? };
        if ct == UIA_EditControlTypeId {
            return Some(element);
        }
        // aid matched but control_type wrong — log + skip
        warn!(
            "v0.3.8: find_automation_id_edit: aid='{aid}' matched but \
             ControlType={ct:?} is not Edit; skipping"
        );
    }
    None
}
```

**额外保护**:可以同时限定 `automation_id='1001'` AND `name='文件名:'` (中文 UI 双保险),但这增加耦合,不强求。

### 3.2 🔴 A2 [HIGH] — SetValue 后必须 read back verify

#### 3.2.1 问题

**Claude 当前 plan**(v0.3.8 §4.1):
```rust
if let Some(ref edit) = edit_1001 {
    unsafe {
        let value: IUIAutomationValuePattern =
            edit.GetCurrentPatternAs(UIA_ValuePatternId)?;
        value.SetValue(&BSTR::from(target_path))?;
    }
    if should_commit { commit_via_uia(...) }
    return Ok(DialogOutcome::AddressBarWritten);
}
```

**问题**:`SetValue` 可能**静默失败**(WinUI 3 wrapper 屏蔽 inner Edit 的 SetValue)。
- `SetValue` 返回 Ok 不代表 dialog 实际写入
- 类似问题:focus-18 v0.3.1 报告"Auto-Confirm 工作",但实际可能是 SetValue 静默失败 + 没 commit 也"看起来没问题"

#### 3.2.2 修复方案

```rust
if let Some(ref edit) = edit_1001 {
    unsafe {
        let value: IUIAutomationValuePattern =
            edit.GetCurrentPatternAs(UIA_ValuePatternId)?;
        value.SetValue(&BSTR::from(target_path))?;
        
        // v0.3.8 (Mavis A2 [HIGH]): verify SetValue actually wrote
        let readback = value.CurrentValue()?;
        let readback_str = readback.to_string();
        if readback_str != target_path {
            warn!(
                "v0.3.8: SetValue verification FAILED for automation_id='1001'. \
                  Wrote='{}', Read back='{}'. WinUI 3 wrapper may be blocking. \
                  Treating as unsupported.",
                target_path, readback_str
            );
            state.inc_unsupported_dialog();
            return Ok(DialogOutcome::Unsupported);
        }
        info!(
            "v0.3.8: SetValue verified for automation_id='1001'. \
             Read back='{}' matches target='{}'.",
            readback_str, target_path
        );
    }
    if should_commit {
        if let Err(e) = commit_via_uia(best_button.as_ref(), None) {
            warn!("commit after 1001 SetValue failed: {e}");
        }
    }
    return Ok(DialogOutcome::AddressBarWritten);
}
```

**作用**:
- SetValue 后 read back,如果不匹配 → 判定 WinUI 3 wrapper 屏蔽 → 返回 Unsupported
- 避免 focus-18 的"静默成功"假象

**副作用**:SetValue → verify 1.5 倍 UIA 调用次数(每个 dialog 多 1 次 CurrentValue)。但 inventory 阶段已经收集所有 element,SetValue 后再 read 不需要重新遍历。

### 3.3 ⚠️ A3 [MEDIUM] — 默认 should_commit=false 的 UX 风险

#### 3.3.1 Claude v0.3.8 当前决策

**Claude v0.3.8 §4.1**:
```rust
if should_commit {
    if let Err(e) = commit_via_uia(best_button.as_ref(), None) {
        warn!("commit after 1001 SetValue failed: {e}");
    }
}
```

**`should_commit` 来源**(`writer.rs`):
```rust
let should_commit = if auto_confirm {
    state.try_mark_committed(hwnd_u32)
} else {
    false       // ← 默认 false
};
```

**默认 should_commit=false 的原因**(沿用 focus-18 默认):
- Auto-Confirm 默认 OFF
- 安全起见,不自动点 Save
- focus-18 v0.3.1 当时也是 default OFF

#### 3.3.2 问题 — 用户会再次抱怨"filename 被改"

**场景预测**(Claude v0.3.8 §8 已预测):

| 场景 | 用户感知 |
|---|---|
| Edge Modern Save As(无 flag,默认 should_commit=false)| **1001 SetValue 写入 path,用户看到 filename 框被改 → 用户必须手动点 Save** |
| Edge Modern Save As + Auto-Confirm ON | **1001 SetValue + Invoke Save → dialog 自动关闭** |

**风险**:**默认场景**(大多数用户不开 Auto-Confirm)下,用户仍会看到 "filename 被改",只是这次是合法的(因为是 IFileDialog 兼容 + 用户可手动 Save)。

**但用户此前一直 reject "filename 被改" 的语义**:不区分"自动 Save" vs "手动 Save",只要看到 filename 字段被改就 reject。

#### 3.3.3 修复方案 — 3 个选项

**选项 1**:默认 should_commit=true + Auto-Confirm 强制 ON
- 优点:99% 场景用户看到 dialog 自动关闭,根本不感知"filename 被改"
- 缺点:违反 focus-18 安全默认

**选项 2**:保留 should_commit=false,但 toolbar 提示更清晰
- "默认:filename 写入 + 用户手动点 Save"
- "启用 Auto-Confirm:filename 写入 + 自动点 Save"
- 优点:用户可控
- 缺点:仍有用户抱怨"filename 被改"(虽然语义不同)

**选项 3**(推荐):保留 should_commit=false,但在 v0.3.8 实施后立刻 user-verify U-V1 (Edge WinUI 3 wrapped + 默认状态)
- 如果用户仍抱怨 → 改回 v0.3.6 (L2-1 不写)
- 如果用户接受 → ship v0.3.8

#### 3.3.4 我的推荐 — 选项 2 + 选项 3 组合

**v0.3.8 实施**:
- 保留 `should_commit=false` 默认(沿用 focus-18)
- toolbar 菜单明确分两个状态
- 实施后立即 user-verify U-V1,根据结果决定

**toolbar 文案建议**(`index.js`):
```js
// Auto-Confirm 描述(当前):
'Auto-Confirm: ' + (autoConfirm
    ? 'ON (next push will auto-save once per dialog)'
    : 'OFF (you click Save manually)')

// v0.3.8 改进:
'Auto-Confirm: ' + (autoConfirm
    ? 'ON (Save button auto-clicked after sync)'
    : 'OFF (filename written, you click Save manually)')
```
