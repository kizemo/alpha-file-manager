## 3. v0.3.9 风险评估 + 3 处改进

### 3.1 🟡 B1 [HIGH] — `is_winui3_wrapped` 应限定 ControlType

#### 3.1.1 问题

**当前 `is_winui3_wrapped` 实现**(L692-704):
```rust
fn is_winui3_wrapped(elements: &IUIAutomationElementArray) -> bool {
    // ...遍历所有 elements
    if aid == "FileNameControlHost" {
        return true;
    }
}
```

**问题**:**只检查 `automation_id == "FileNameControlHost"`,不限定 ControlType**。

**实际 inventory(从之前的截图)**:
- `automation_id='FileNameControlHost'` name='文件名:' (Pane 50003)← **目标**
- 但其他 dialog 可能有相同 `automation_id='FileNameControlHost'` 是其他 ControlType

**风险**:
- 某些第三方 dialog 可能用类似名字作为非 Pane 控件 → 误判
- WinUI 3 inner content 可能有 Pane 名为 'FileNameControlHost' 但实际不是 wrapper

#### 3.1.2 修复方案

```rust
fn is_winui3_wrapped(elements: &IUIAutomationElementArray) -> bool {
    let count = unsafe { elements.Length() }.ok().unwrap_or(0);
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok() };
        if let Some(elem) = element {
            let aid = current_automation_id(&elem);
            if aid == "FileNameControlHost" {
                // B1 [HIGH]: 限定 ControlType = Pane(FileNameControlHost 是 Pane 50003)
                // 同时限定 name 包含 "文件名"(避免误匹配)
                let ct = unsafe { elem.CurrentControlType().ok() };
                let name = current_name(&elem);
                if ct == Some(UIA_PaneControlTypeId) && name.contains("文件名") {
                    return true;
                }
                warn!(
                    "v0.3.9: 'FileNameControlHost' aid matched but \
                     ControlType={ct:?} or name='{name}' is not Pane/文件名; skipping"
                );
            }
        }
    }
    false
}
```

**作用**:
- 限定 ControlType = Pane(FileNameControlHost 应该是 Pane 50003)
- 限定 name 包含"文件名"(中英文 UI 都覆盖)
- 避免误匹配其他 dialog 的同名元素

**工作量**:5 min(添加限定 + warn 日志)

### 3.2 🟡 B2 [MEDIUM] — fallback outer class 检查

#### 3.2.1 问题

**`is_win_u3_wrapped` 只检查 inner content**,不验证 outer window class。

**实际上**:
- WinUI 3 wrapped dialog outer class 可能仍是 `#32770`(沿用 Win32 dialog convention)
- 但 WinUI 3 native 的 outer class 可能不同(如 `WinUIDesktopWin32WindowClass`)
- 区分 outer class 可以作为 fallback 防御

#### 3.2.2 修复方案

```rust
fn classify_outer_class(dialog_hwnd: u32) -> &'static str {
    // 类似 main.rs::classify_app 的简化版
    use windows::Win32::Foundation::HWND;
    use windows::Win32::UI::WindowsAndMessaging::GetClassNameW;
    let h = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let mut buf = [0u16; 256];
        let len = GetClassNameW(h, &mut buf);
        if len > 0 {
            let class = String::from_utf16_lossy(&buf[..len as usize]);
            if class.starts_with("#32770") {
                return "IFileDialog_Win32";  // 标准 Win32 dialog
            }
            if class.contains("WinUI") || class.contains("XAML") {
                return "WinUI_3_Native";
            }
            return "Unknown";
        }
        "unknown"
    }
}

// 在 inject_via_uia 中:
if is_winui3_wrapped(&elements) {
    // ... (现有 Unsupported 路径)
} else {
    // B2 [MEDIUM]: 检查 outer class 作为 fallback 防御
    let outer_class = classify_outer_class(dialog_hwnd);
    if outer_class == "WinUI_3_Native" {
        warn!("v0.3.9: outer class is WinUI_3_Native but FileNameControlHost not found. \
              Treating as unsupported to be safe.");
        state.inc_unsupported_dialog();
        return Ok(DialogOutcome::Unsupported);
    }
    // 然后才走 find_ifiledialog_edit
    if let Some(ref edit) = find_ifiledialog_edit(&elements) {
        // ...
    }
}
```

**作用**:outer class + inner content 双重检查,降低误判。

**工作量**:10 min(classify_outer_class + 集成)

### 3.3 🟢 B3 [LOW] — 启动 grace period 中抑制 WinUI 3 wrapped 通知

#### 3.3.1 问题

**v0.3.9 WinUI 3 wrapped 检测 → `inc_unsupported_dialog()` → extension 弹通知**

**首次激活 Edge**:
- t=0: Edge tip
- t=0: registerDropdown
- t=0+: 用户开 Edge,WinUI 3 Save As 弹出
- t=0+: sidecar 立即检测 → inc_unsupported_dialog → extension 弹通知
- 启动 30s 内可能弹 Edge tip + unsupported 通知(sidecar 启动慢时)

#### 3.3.2 修复方案

**沿用 A3 / v0.3.8 grace period**(`release/extension/dist/index.js`):
```js
// B3 [LOW]: grace period 30s 内对 unsupported dialog 通知抑制
async function checkHealth() {
    // ... 现有逻辑 ...
    if (parsed && typeof parsed.unsupported_dialog_count === 'number') {
        const newCount = parsed.unsupported_dialog_count;
        if (lastUnsupportedDialogCount === -1) {
            lastUnsupportedDialogCount = newCount;
        } else if (newCount > lastUnsupportedDialogCount) {
            const now = Date.now();
            // B3: grace period 内不弹通知(避免启动 spam)
            if (now - bootStartedAt >= BOOT_GRACE_MS
                && now - lastUnsupportedNotifyTs >= UNSUPPORTED_NOTIFY_THROTTLE_MS) {
                // 弹通知
            }
        }
    }
}
```

**作用**:30 秒 boot grace period + 5 分钟 throttle(沿用)+ 在 grace period 内不弹 unsupported 通知

**工作量**:5 min(修改 `checkHealth` 函数)
