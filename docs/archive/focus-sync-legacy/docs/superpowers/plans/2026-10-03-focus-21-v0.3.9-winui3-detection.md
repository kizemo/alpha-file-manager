## 2. v0.3.9 修复方案

### 2.1 🔴 核心 fix:检测 FileNameControlHost

**文件**:`sigma-listary-spike/src/uia_inject.rs`

**新增 helper**(Mavis 规则 21 扩展):
```rust
/// v0.3.9: detect WinUI 3 wrapped dialog via FileNameControlHost.
/// Returns true if dialog has FileNameControlHost (Pane 50003), which is
/// the WinUI 3 wrapper around the inner IFileDialog. WinUI 3 wrapped
/// dialogs accept UIA SetValue to the inner 1001/1148 Edit but the
/// user sees the path in the filename field for 2-6 seconds before
/// Invoke Save closes the dialog. This visual pollution is rejected
/// by the user (12 rounds of feedback).
///
/// True IFileDialog (Edge Legacy, Notepad Save As, Photos) does NOT
/// have FileNameControlHost — only the bare 1001/1148 Edit.
fn is_winui3_wrapped(elements: &IUIAutomationElementArray) -> bool {
    let count = unsafe { elements.Length() }.ok().unwrap_or(0);
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok() };
        if let Some(elem) = element {
            let aid = current_automation_id(&elem);
            if aid == "FileNameControlHost" {
                return true;
            }
        }
    }
    false
}
```

**修改 `inject_via_uia` 末尾分支**:
```rust
// v0.3.9: 在 find_ifiledialog_edit 之前先检测 WinUI 3 wrapped
if is_winui3_wrapped(&elements) {
    warn!(
        "v0.3.9: WinUI 3 wrapped dialog detected (FileNameControlHost present). \
         Per 12-round user feedback, DO NOT write path to filename field \
         (user rejected 'filename modified' reports in every focus-21 round). \
         Returning Unsupported so extension can show 'enable edge-legacy-file-picker' notification. \
         target='{target_path}'"
    );
    state.inc_unsupported_dialog();
    return Ok(DialogOutcome::Unsupported);
}

// 然后才走 find_ifiledialog_edit (只对 true IFileDialog)
if let Some(ref edit) = find_ifiledialog_edit(&elements) {
    // ... 1001/1148 SetValue + Auto-Commit(沿用 v0.3.8)
}
```

## 8. 总结:12 轮 review 以来唯一可信的 fix 方向

**核心论点**:

1. **A9 错**:`should_commit=true` + 1001 SetValue 让 WinUI 3 wrapped dialog 写 filename + 6 秒后关闭
2. **用户拒收中间态** — 12 轮一致反馈
3. **唯一方向**:精确区分 WinUI 3 wrapped vs true IFileDialog → 仅后者 SetValue + Auto-Commit
4. **区分标志**:`automation_id='FileNameControlHost'`(Pane 50003)存在 = WinUI 3 wrapped

**v0.3.9 = 12 轮 review 以来第一个完全基于 sidecar log 证据 + 精确 WinUI 3 检测的方案**:
- ✅ L1 修了 PUSH=502(v0.3.7)
- ✅ A1/A2/A4/A6/A7/A8 helper 完整(v0.3.8)
- ✅ WinUI 3 wrapped 检测(`FileNameControlHost`)= 新增 fix
- ✅ True IFileDialog 路径保留 SetValue + Auto-Commit(沿用 v0.3.8)
- ✅ WinUI 3 wrapped 路径 return Unsupported + 通知(v0.3.6 思路但更精确)

**风险等级**:🟢 **低**(只加 helper + 检测分支)
**价值等级**:🟢 **高**(消除用户 12 轮 reject 的核心痛点)
**总评**:v0.3.9 是 12 轮 review 以来**最接近用户实际诉求**的方案,前提是 FileNameControlHost 确实是 WinUI 3 wrapped 的稳定标志(U-V1 + U-V4 verify)。
