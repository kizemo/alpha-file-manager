### 2.3 真实 bug 定位

**v0.3.8 的 SetValue 行为**:
```rust
value.SetValue(&BSTR::from(target_path))?;  // "C:\evid"
```

写入的是**完整路径**到 1001 Edit。对 WinUI 3 wrapped dialog 来说,FileNameControlHost(Pane 50003)显示这个值,用户看到 `filename = "C:\evid"`。心理预期是 `filename = "WeavePage_3.0.0_x64-setup.exe"`(用户的原始文件名)。

**正确 fix 应该**:
- 不写完整路径到 filename Edit
- 用其他机制导航目录(address bar / 面包屑 / tree view / Ctrl+L SendInput)
- 保持 filename Edit 显示用户的原始文件名

## 3. 修复方案(v0.4.0)

### 3.1 设计目标

| 目标 | 指标 | 测量方式 |
|---|---|---|
| 不污染 filename Edit | filename 字段值保持用户原始输入 | sidecar log: read-back filename == dialog initial filename |
| 导航到目标目录 | dialog 顶部路径栏显示 target_path | 用户截图确认 |
| Auto-Commit 不延长 | Invoke Save 在 SetValue 后 < 500ms | spike.log 时间戳间隔 |
| True IFileDialog (Win32) | 仍按 v0.3.8 行为(Win32 把路径当 filename 接受) | Phase A1 已验证 |
| Chromium 41477 | 仍按 v0.3.8 行为(写完整路径到地址栏) | spike-report 已验证 |

### 3.2 实现策略

**3 路径并行,按 dialog 特征选择**:


**改动 C**:新增 `find_navigation_address_bar` helper(查找地址栏/面包屑)

```rust
/// v0.4.0: locate the navigation address bar / breadcrumb in a dialog tree.
/// Returns the first Edit (ControlType=50004) whose automation_id matches
/// common navigation patterns: "41477" (Chromium), "SearchEditBox", or
/// whose name contains "地址" / "路径" / "address" / "path" / "location".
///
/// Used as an alternative write target when the filename Edit should NOT be
/// polluted (WinUI 3 wrapped dialogs interpret filename Edit as literal
/// filename, not as navigation target).
fn find_navigation_address_bar(
    elements: &IUIAutomationElementArray,
) -> Option<IUIAutomationElement> {
    let count = unsafe { elements.Length() }.ok()?;
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        let ct = unsafe { element.CurrentControlType().ok()? };
        // Skip 1001/1148 (filename Edit) — already handled separately.
        let aid = current_automation_id(&element);
        if ct == UIA_EditControlTypeId {
            // Chromium address bar takes priority.
            if aid == "41477" {
                return Some(element);
            }
            // Generic address bar: search for "address", "path", "location",
            // "地址", "路径", "位置" in name.
            let name = current_name(&element).to_lowercase();
            if name.contains("地址")
                || name.contains("路径")
                || name.contains("位置")
                || name.contains("address")
                || name.contains("path")
                || name.contains("location")
            {
                return Some(element);
            }
        }
    }
    None
}
```

**改动 D**:在 `inject_via_uia` 中,address_bar 检测之后插入 WinUI 3 wrapped 的"basename"分支

```rust
// v0.4.0: address bar / breadcrumb fallback for WinUI 3 wrapped dialogs.
// The 41477 branch above handles Chromium; for native IFileDialog we use
// find_ifiledialog_edit (writes FULL path, which Win32 dialogs accept as
// navigation). But for WinUI 3 wrapped dialogs (FileNameControlHost present,
// 1001/1148 present as inner Edit), writing FULL path pollutes the visible
// filename. So for those we write ONLY the basename to the filename Edit,
// and try to use a navigation address bar / breadcrumb for the directory.
//
// Detection: FileNameControlHost present (from removed is_winui3_wrapped —
// we now inline the check to avoid an extra function call):
let has_filename_host = {
    let count = unsafe { elements.Length() }.ok().unwrap_or(0);
    (0..count).any(|i| {
        unsafe { elements.GetElement(i).ok() }
            .map(|e| current_automation_id(&e) == "FileNameControlHost")
            .unwrap_or(false)
    })
};

if has_filename_host {
    // WinUI 3 wrapped: write basename to filename Edit + try breadcrumb.
    let basename = std::path::Path::new(target_path)
        .file_name()
        .and_then(|n| n.to_str())
        .unwrap_or("");

    // Find filename Edit (we still need to update it).
    if let Some(ref edit) = find_ifiledialog_edit(&elements) {
        // Write ONLY basename (or leave empty) to avoid pollution.
        let value: IUIAutomationValuePattern =
            unsafe { edit.GetCurrentPatternAs(UIA_ValuePatternId)? };
        unsafe { value.SetValue(&BSTR::from(basename))? };
        info!(
            "v0.4.0: WinUI 3 wrapped — wrote basename='{}' to filename Edit \
             (preserves user's intended filename). target='{}'",
            basename, target_path
        );

        // Try to set the directory via navigation address bar if available.
        if let Some(addr_bar) = find_navigation_address_bar(&elements) {
            let addr_value: IUIAutomationValuePattern =
                unsafe { addr_bar.GetCurrentPatternAs(UIA_ValuePatternId)? };
            unsafe { addr_value.SetValue(&BSTR::from(target_path))? };
            info!(
                "v0.4.0: WinUI 3 wrapped — wrote target='{}' to navigation address bar",
                target_path
            );
        } else {
            warn!(
                "v0.4.0: WinUI 3 wrapped — no navigation address bar found. \
                 User must navigate manually. target='{}'",
                target_path
            );
            // Notify via state (extension polls /health for unsupported count).
            state.inc_unsupported_dialog();
            return Ok(DialogOutcome::Unsupported);
        }

        // Don't auto-commit for WinUI 3 wrapped (user may want to review).
        return Ok(DialogOutcome::AddressBarWritten);
    }
}
```
