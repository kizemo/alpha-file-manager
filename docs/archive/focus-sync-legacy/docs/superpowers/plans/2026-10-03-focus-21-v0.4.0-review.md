## 2. v0.4.0 plan 代码 8 处需要调整

### 2.1 🔴 C1 [HIGH] — §5.2 预期与代码自相矛盾

**问题**:

**v0.4.0 §5.2 U-V1 预期**:
> ✅ Save As dialog filename 字段保持 `WeavePage_3.0.0_x64-setup.exe`(不被改为 `C:\evid`)

**v0.4.0 §3.3 改动 D 代码 L285-289**:
```rust
if let Some(ref edit) = find_ifiledialog_edit(&elements) {
    // Write ONLY basename (or leave empty) to avoid pollution.
    let value: IUIAutomationValuePattern =
        unsafe { edit.GetCurrentPatternAs(UIA_ValuePatternId)? };
    unsafe { value.SetValue(&BSTR::from(basename))? };   // ← 把 basename 写入 Edit!
    info!(
        "v0.4.0: WinUI 3 wrapped — wrote basename='{}' to filename Edit \
         (preserves user's intended filename). target='{}'",
        basename, target_path
    );
}
```

**实际行为**:
- `target_path = "C:\\evid"` 是目录
- `basename("C:\\evid")` = `"evid"`(目录最后一段)
- SetValue `evid` 到 1001 Edit(就是 filename Edit)
- 用户原本 filename = `WeavePage_3.0.0_x64-setup.exe`
- **现在 filename = `evid`(目录名污染)**

**§5.2 预期"filename 保持 WeavePage_3.0.0_x64-setup.exe" 与代码行为矛盾**:
- 代码确实"改 SetValue"为 basename(`evid`),不是"保持原样"
- 注释说"preserves user's intended filename" 但**用户的 intended filename 是 `WeavePage_3.0.0_x64-setup.exe`,不是 `evid`**

**用户视角**:
- v0.3.8: filename 显示 `C:\evid` → reject
- v0.4.0: filename 显示 `evid` → **仍可能 reject**(虽然比 v0.3.8 短)

#### 修复方案

**方案 A**:**完全不动 filename Edit**(真正不污染):
```rust
if has_filename_host {
    // C1 [HIGH]: WinUI 3 wrapped — DON'T touch filename Edit at all.
    // Reason: any SetValue to 1001/1148 Edit pollutes the visible filename
    // (user typed "WeavePage_3.0.0_x64-setup.exe"; setting it to anything
    // else — even a basename — is pollution from the user's perspective).
    info!(
        "v0.4.0: WinUI 3 wrapped — leaving filename Edit untouched. \
         Attempting navigation address bar / breadcrumb. target='{}'",
        target_path
    );

    // Try to set the directory via navigation address bar if available.
    if let Some(addr_bar) = find_navigation_address_bar(&elements) {
        let addr_value: IUIAutomationValuePattern =
            unsafe { addr_bar.GetCurrentPatternAs(UIA_ValuePatternId)? };
        unsafe { addr_value.SetValue(&BSTR::from(target_path))? };
        
        // C2 [HIGH]: read back verify on address bar
        let readback = unsafe { addr_value.CurrentValue() }?;
        let readback_str = readback.to_string();
        if !path_matches(&readback_str, target_path) {
            warn!(
                "v0.4.0: address bar SetValue verification FAILED. \
                 Wrote='{}', Read back='{}'. Notify user to navigate manually.",
                target_path, readback_str
            );
            state.inc_unsupported_dialog();
            return Ok(DialogOutcome::Unsupported);
        }
        info!(
            "v0.4.0: WinUI 3 wrapped — wrote target='{}' to navigation address bar \
             (read-back verified). filename Edit untouched.",
            target_path
        );
        // Don't auto-commit for WinUI 3 wrapped (user may want to review).
        return Ok(DialogOutcome::AddressBarWritten);
    } else {
        warn!(
            "v0.4.0: WinUI 3 wrapped — no navigation address bar found. \
             User must navigate manually. target='{}'",
            target_path
        );
        state.inc_unsupported_dialog();
        return Ok(DialogOutcome::Unsupported);
    }
}
```

**方案 B**:**可选:写 basename + 注释**(Claude 当前方案但不改):
- 接受 basename 写入是"次污染"
- 比起完整路径污染,basename 短一些
- 用户可能接受或拒绝

**推荐**:**方案 A**(完全不动 filename Edit)
- 真正"不污染"
- 12 轮 reject 的"filename 被改"彻底解决
- 如果 address bar 找不到,返回 Unsupported + 通知(用户手动)

### 2.3 🟡 C3 [MEDIUM] — basename 函数应使用现有 helper

**问题**:

**v0.4.0 §3.3 改动 D L279-282**:
```rust
let basename = std::path::Path::new(target_path)
    .file_name()
    .and_then(|n| n.to_str())
    .unwrap_or("");
```

**现有 `basename()` helper(uia_inject.rs L141-147)**:
```rust
fn basename(path: &str) -> &str {
    let p = path.trim_end_matches(['\\', '/']);
    match p.rfind(['\\', '/']) {
        Some(idx) => &p[idx + 1..],
        None => p,
    }
}
```

**差异**:
- `std::path::Path::new("C:\\evid\\").file_name()` 在 Windows 上 = `Some("evid")`(Windows 处理 `\\`)
- 现有 `basename("C:\\evid\\")` = `"evid"`(直接 `rfind`)

**两者结果接近**,但用现有 helper:
- 已测试覆盖(7 个 basename 测试)
- 与其他代码路径一致
- 处理 `/` 路径分隔符

#### 修复方案

```rust
// C3 [MEDIUM]: 使用现有 basename() helper
let basename_str = basename(target_path);
if basename_str.is_empty() {
    warn!("v0.4.0: basename extraction failed for '{}'", target_path);
```

### 2.4 🟡 C4 [MEDIUM] — find_navigation_address_bar 优先级错

**问题**:

**v0.4.0 §3.3 改动 C L223-252**:
```rust
fn find_navigation_address_bar(...) -> Option<IUIAutomationElement> {
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        let ct = unsafe { element.CurrentControlType().ok()? };
        let aid = current_automation_id(&element);
        if ct == UIA_EditControlTypeId {
            // Chromium address bar takes priority.
            if aid == "41477" {
                return Some(element);  // ← 错!
            }
            ...
        }
    }
}
```

**问题**:
- `aid == "41477"` 是 Chromium Save As 的 address bar
- 但 `inject_via_uia` 已有 41477 分支(L439-453)处理 Chromium
- WinUI 3 wrapped 不会同时有 41477(那是 Chromium 标志)
- 这里检查 41477 是 dead code(永远不会命中,因为如果 dialog 有 41477,早就走 41477 分支返回了)

#### 修复方案

```rust
// C4 [MEDIUM]: 41477 应被排除(已被 inject_via_uia 41477 分支处理)
fn find_navigation_address_bar(
    elements: &IUIAutomationElementArray,
) -> Option<IUIAutomationElement> {
    let count = unsafe { elements.Length() }.ok()?;
    for i in 0..count {
        let element = unsafe { elements.GetElement(i).ok()? };
        let ct = unsafe { element.CurrentControlType().ok()?;
        // Skip 41477 (Chromium, already handled) and 1001/1148 (filename Edit)
        let aid = current_automation_id(&element);
        if aid == "41477" || aid == "1001" || aid == "1148" {
            continue;
        }
        if ct == UIA_EditControlTypeId {
            // Generic address bar / search box
            let name = current_name(&element).to_lowercase();
            if name.contains("地址")
                || name.contains("路径")
                || name.contains("位置")
                || name.contains("address")
                || name.contains("path")
                || name.contains("location")
                || name.contains("search")  // search box often accepts path
            {
                return Some(element);
            }
        }
    }
    None
}
```

**改进**:
- 跳过 41477/1001/1148(已被其他分支处理)
- 加 `search`(search box 经常接受路径)
