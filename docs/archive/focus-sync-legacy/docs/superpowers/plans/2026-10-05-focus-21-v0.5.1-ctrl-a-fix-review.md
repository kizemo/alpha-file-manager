## 1. 修复方向判断(✅ 方向正确)

### 1.1 用户实测证据可信度高

### 1.2 根因诊断精准

Plan 推断:
> "Chromium omnibox: Ctrl+L = focus AND select-all (标准行为)

## 2. 🔴 I1 — 冗余 Ctrl↓ push(代码 vs 注释矛盾)

### 2.1 Bug 位置

`§4.3 修复后代码 line 179`:

```rust
// Step 3: Ctrl down, L down — focus Chromium's address bar.
inputs.push(make_key(VK_CONTROL.0, 0));   // (a) Ctrl↓
inputs.push(make_key(VK_L.0, 0));         // (b) L↓

// v0.5.1 (2026-10-05 user feedback): Ctrl+L alone does NOT select-all
// in Edge WinUI 3 Save As dialog (it only focuses). Typing then
// appends to existing text. Add Ctrl+A to force select-all before typing.
inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));  // (c) L↑

// Step 3b: Ctrl+A — select all text in current focus (file name box).
inputs.push(make_key(VK_CONTROL.0, 0));  // (d) ← ⚠️ REDUNDANT
inputs.push(make_key(0x41, 0));           // (e) A↓
inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));   // (f) A↑
inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0)); // (g) Ctrl↑
```

### 2.2 注释 vs 代码矛盾

代码注释 "Ctrl still down from Step 3" 暗示 Ctrl 已被按下,**不应该**再 push 一个 Ctrl↓。

但实际代码 (d) 又 push 了一个 Ctrl↓。这是 **bug**:要么删 push(d),要么改注释。

### 2.3 实际后果:
- 后端键盘 input queue 收到 **2 个 Ctrl↓**(a 和 d)+ 1 个 Ctrl↑(g)。
- 大多数 Windows 程序会视为"按住 Ctrl"(合成后等价于 1 Ctrl↓ + 1 Ctrl↑),但：
  - 某些 WinUI 3 / Chromium 子系统会把这个状态机当作"Ctrl 释放后重新按下"
  - 可能导致 Chromium 的 Ctrl 状态 tracking 出现 edge case bug
  - **不是 ship-blocker**,但违反 "最小改动" 原则

### 2.4 修复

**删除 (d) 行**:

```rust
inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));  // (c) L↑
// Ctrl is still held from (a) — no need to re-press

inputs.push(make_key(0x41, 0));                          // A↓
inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));          // A↑
inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));  // Ctrl↑ (final release)
```

### 2.5 Event count 影响

| | 旧 plan 计算 | 实际 plan 代码 | 修复后 |
|---|---|---|---|
| C:\evid (7 chars) | 13 | 14 | **13** |

Plan §4.4 表格声称 "C:\evid (7) → 13 events",**但当前 plan 代码实际是 14**(因为冗余 Ctrl↓)。

修复后 count 才匹配 plan 声称的 13。

## 3. 🔴 I2 — Filename 污染假设未 verify

### 3.1 13 轮 root cause 重申

v0.5.1 review §1.2 已经确认:
> "WinUI 3 wrapped Edge Save As dialog 的 1001 Edit 同时承担两个角色:
>   1. **filename 显示字段**
>   2. **address bar 输入**"

也就是说,**WinUI 3 wrapped Save As 中,1001 Edit = filename 显示 = Chromium 内部 address bar**,两者是同一个 UI 元素。

### 3.2 Ctrl+A 在 1001 上的后果

如果 address bar = 1001(filename Edit),那么:
1. PUSH C:\evid
2. SendInput Ctrl+L → focus 1001 (焦点切到该 Edit)
3. SendInput Ctrl+A → **选中 1001 中的所有文本(可能用户原始 filename)**
4. SendInput path chars → **替换 1001 文本为 C:\evid**
5. 最终:1001 = "C:\evid" → **filename 仍然污染!**

这违背了 13 轮 review 的核心诉求:**"不要把路径写进 filename 字段"**。

### 3.3 验证方法(实施前必做)

**A. 截图实测**(最简单):用户实测时同时截图 filename 字段 + address bar/breadcrumb:
- 如果 filename 字段保持用户原始值 → Ctrl+A + type 只动 address bar (WinUI 3 内部逻辑可能区分)
- 如果 filename 字段变成路径 → Ctrl+A 选中了 filename 文本,直接污染

**B. UIA inventory log**(更确定):dump 当前 dialog 的所有 1001 Edit 的 Name/LocalizedType,看是否有"filename"标签。

### 3.4 可能的真实情况(基于当前用户反馈推断)

用户说 "目录可以同步到下载弹窗正确的地址栏了",说明:
- breadcrumb 正确更新 ✓
- **未提及** filename 是否也变了

最可能情况(我的推断):
- 1st PUSH "C:\boost_weasel":用户在 dialog 中没输入 filename → 1001 是空的 → typing 直接写入 1001 = filename 被污染 = "C:\boost_weasel"
- 2nd PUSH "C:\evid":1001 已有 "C:\boost_weasel",Ctrl+L 只 focus(不 select),光标在末尾 → typing append → "C:\boost_weaselC:\evid"

如果用户从未在 filename 字段输入任何内容,1st PUSH 之后 1001 = path,filename 已被污染(但用户没注意,因为用户还没决定 filename)。

**plan 没问用户:1st PUSH 之后,filename 字段显示什么?** 这是判断 filename 是否污染的关键。

### 3.5 如果 I2 confirmed(filename 被污染)— Ctrl+A fix 不够

需要回退到 v0.5.0 行为 + Edge legacy flag 提示。这是 §7 fallback D3:
> "用 UIA SetValue 1001 Edit 为空字符串先(但会触发 filename pollution → 退回 v0.5.0 行为)"

或者考虑 D4:
> "接受拼接 + extension 端做 dedup(每次 push 只发 path 不同部分)"

D4 实施要点:extension 比较 current address bar 文本和 target path,**只 type 不同的字符**。需要 SendInput 之前先 ReadBack address bar 内容。这是个不错的 fallback。

### 3.6 plan 需要补充的实测问题

**应该在 plan §6.4 加一个问题**:
> "Q1: 实施 Ctrl+A fix 后,1st PUSH 之后 filename 字段显示什么? 用户原始 filename 还在吗?"

如果用户答 "filename 被改成 C:\boost_weasel" → I2 confirmed,Ctrl+A fix 不够,需要重新设计。

## 4. 🟡 I3 — KEYEVENTF_UNICODE 缺 KEYUP

### 4.1 当前代码(已在 v0.5.1 ship)

```rust
// Step 4: type the path char-by-char using KEYEVENTF_UNICODE
for ch in target_path.encode_utf16() {
    inputs.push(make_unicode(ch));  // ← 只 push press,没有 release
}
```

`make_unicode` 函数:
```rust
fn make_unicode(ch: u16) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(0),
            wScan: ch,
            dwFlags: KEYEVENTF_UNICODE,  // ← 只 keydown flag
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}
```

### 4.2 问题

MSDN `SendInput` 文档:
> "To simulate pressing and releasing a key, send two events. The first event should specify KEYEVENTF_KEYDOWN for the wVk parameter (or wScan for KEYEVENTF_UNICODE) and the second event should specify KEYEVENTF_KEYUP."

`KEYEVENTF_UNICODE` 也需要 keyup events。当前代码**只发 press,不发 release**。

实际行为(实际可能 work):
- 单字符 unicode input(无 release),Chromium 视为 1 个 keystroke(实际是合成 "key down + auto-release" by OS)
- 但某些应用会忽略这种 input,或视为 key-hold
- 多个连续 unicode chars 可能被识别为 "dead key + key"(例如输入 0x0301 + 0x0300 会合成,而不是分别输入)

### 4.3 修复

每个 unicode char 发 **press + release**:

```rust
// D2 + I3 fix: KEYEVENTF_UNICODE needs both press + release events
fn make_unicode(ch: u16) -> INPUT {
    make_unicode_key(ch, KEYEVENTF_UNICODE)  // press
}

fn make_unicode_release(ch: u16) -> INPUT {
    make_unicode_key(ch, KEYEVENTF_UNICODE | KEYEVENTF_KEYUP)  // release
}

fn make_unicode_key(ch: u16, flags: KEYBD_EVENT_FLAGS) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(0),
            wScan: ch,
            dwFlags: flags,
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}

// 使用:
for ch in target_path.encode_utf16() {
    inputs.push(make_unicode(ch));
    inputs.push(make_unicode_release(ch));
}
```

或者更简单,用 `make_key` 传入 unicode chars:
```rust
for ch in target_path.encode_utf16() {
    inputs.push(make_key_with_unicode(ch, KEYEVENTF_UNICODE));  // press
    inputs.push(make_key_with_unicode(ch, KEYEVENTF_UNICODE | KEYEVENTF_KEYUP));  // release
}
```

### 4.4 影响

| path | 当前 events | 修复后 events |
|---|---|---|
| C:\evid (7 chars) | 7 (path) | 14 (press + release) |
| C:\downloads (14 chars) | 14 | 28 |
| C:\boost_weasel (15 chars) | 15 | 30 |

总 event count 加倍。对于长路径可能影响 performance(SendInput 是同步 API),但对短路径(7-15 chars)无影响。

### 4.5 plan 是否应包含此 fix?

**推荐:包含**。理由:
- "修复范围最小化" vs "as long as we're here"
- pre-existing bug 已经导致 1st PUSH 可能不 work(unreported,但理论上)
- Ctrl+A fix 是测试 path chars 行为的最佳时机
- 加 14 个 events 不影响 user-verify 范围

**如不包含**:plan 应明确说"已知 pre-existing bug,留给 v0.5.2 修"。

## 6. ⚠️ WinUI 3 可能同时截 Ctrl+A

### 6.1 风险

WinUI 3 wrapped Edge Save As 已经截了 Ctrl+L 不 select-all。可能类似截 Ctrl+A:
- WinUI 3 中间层可能在 Ctrl+A 之前 eat key event
- 导致 Ctrl+A 不到 Chromium,Chromium 没 select-all
- typing 仍 append

### 6.2 概率

中等。WinUI 3 wrapped 的 keyboard hook 行为在 Save As dialog 上**没公开文档**,只能实测。

### 6.3 plan fallback D1 不够具体

Plan §7 列出:
> "D1: Backspace x 50"

但没设计:
- N=50 是否够?(基于 dialog 最大路径长度)
- Backspace 是 KEYEVENTF_UNICODE 还是虚拟键?(0x08 = VK_BACK,应该是虚拟键)
- Backspace x 50 = 100 events,加 release?
- 如果删过多会怎样?(address bar 是空时,Backspace 不做事)
- 删多了是否污染 filename?

### 6.4 推荐 D1 设计(plan 应补充)

```rust
fn try_sendinput_backspace_clear(dialog_hwnd: u32, max_chars: usize) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        // 先 focus address bar(可能已经在,但保险)
        let mut inputs: Vec<INPUT> = Vec::with_capacity(max_chars * 2);
        inputs.push(make_key(0x08, 0));  // Backspace↓ (focus first)
        ...
```

实际上 D1 设计要先 focus address bar(再次 Ctrl+L),然后 backspace x N(每个 backspace 是 keydown + keyup):

```rust
// Step 1: focus address bar (Ctrl+L)
inputs.push(make_key(VK_CONTROL.0, 0));
inputs.push(make_key(VK_L.0, 0));
inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

// Step 2: Backspace x N(每个 char 1 backspace,够删 max_chars 长 path)
for _ in 0..max_chars {
    inputs.push(make_key(0x08, 0));           // Backspace↓
    inputs.push(make_key(0x08, KEYEVENTF_KEYUP.0));  // Backspace↑
}
```

**问题**:
- 如果 address bar 已经有 user typed filename(如 "myfile.zip"),**backspace 会删 user filename** → 后续 typing 会替换为 path → **filename 仍污染**

所以 D1 与 Ctrl+A 本质相同问题,只是 D1 不依赖 select-all 工作。

### 6.5 更好的 fallback D5(plan 没列)

**D5**:SendInput **Ctrl+L 两次** — 第一次 focus,第二次 toggle focus,可能会 select-all(类似 toggle 行为)。

或者:

**D6**:SendInput **`Home`** 跳到行首 + **`Shift+End`** 选中到行尾,然后 type replace:

```rust
inputs.push(make_key(VK_HOME.0, 0));           // Home↓
inputs.push(make_key(VK_HOME.0, KEYEVENTF_KEYUP.0));
inputs.push(make_key(VK_SHIFT.0, 0));         // Shift↓
inputs.push(make_key(VK_END.0, 0));            // End↓
inputs.push(make_key(VK_END.0, KEYEVENTF_KEYUP.0));
inputs.push(make_key(VK_SHIFT.0, KEYEVENTF_KEYUP.0));
```

Home/End/Shift+End 是非常基础的 Edit 操作,WinUI 3 不太可能截。

## 7. 完整修复方案 1(推荐 A1:只删冗余 Ctrl↓)

### 7.1 diff 形态

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        let mut inputs: Vec<INPUT> = Vec::with_capacity(7 + target_path.len());

        // Step 3: Ctrl+L — focus Chromium's address bar.
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));

        // v0.5.1.1 (2026-10-05 user feedback): Ctrl+L alone does NOT select-all
        // in Edge WinUI 3 Save As dialog (it only focuses). Typing then appends
        // to existing text. Add Ctrl+A to force select-all before typing.
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));

        // Step 3b: Ctrl+A — select all text in current focus.
        // (Ctrl is still held from Step 3; no need to re-press.)
        inputs.push(make_key(0x41, 0));           // A↓
        inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));  // A↑
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0)); // Ctrl↑

        // Step 4: type the path char-by-char using KEYEVENTF_UNICODE
        // (replaces the selection from Ctrl+A).
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
        }

        // (No Enter, no Invoke Save — Rule 47.)

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        let total = inputs.len() as u32;
        if n != total {
            warn!(
                "v0.5.1.1 SendInput: queued {total} events, system accepted only {n}; \
                 foreground-lock likely blocked some events (Mavis D3)"
            );
            return false;
        }
        info!("v0.5.1.1 SendInput Ctrl+L + Ctrl+A + path dispatched ({total} events, no Enter)");
        true
    }
}
```

## 9. 完整修复方案 3(推荐 A3:A2 + D6 Home+Shift+End fallback + 测试)

### 9.1 增量

A2 + 新增 D6 fallback + 新增测试。

/// v0.5.2 D6: Home + Shift+End 强制选中整个 line,比 Backspace 精确
fn try_sendinput_home_shift_end_select(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        let mut inputs: Vec<INPUT> = Vec::with_capacity(10 + target_path.len() * 2);

        // Step 1: focus address bar (Ctrl+L)
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

        // Step 2: Home — 跳到行首
        inputs.push(make_key(VK_HOME.0, 0));
        inputs.push(make_key(VK_HOME.0, KEYEVENTF_KEYUP.0));

        // Step 3: Shift+End — 选中到行尾
        inputs.push(make_key(VK_SHIFT.0, 0));
        inputs.push(make_key(VK_END.0, 0));
        inputs.push(make_key(VK_END.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_SHIFT.0, KEYEVENTF_KEYUP.0));

        // Step 4: type the path (replaces selection)
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
            inputs.push(make_unicode_release(ch));
        }

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        n == inputs.len()
    }
}
