## 0. TL;DR(60 秒)

**用户反馈**:
- ✅ 目录可以同步到下载弹窗正确的地址栏了(进步!)
- ❌ 但更换路径时,新路径**拼接到**原路径,而非替换

**根因**(Phase 1 evidence):
```
1st PUSH C:\boost_weasel → address bar = "C:\boost_weasel"
2nd PUSH C:\evid        → address bar = "C:\boost_weaselC:\evid"  ← 拼接!
3rd PUSH C:\etc         → address bar = "C:\boost_weaselC:\evidC:\etc"  ← 持续拼接
```

SendInput 序列:`Ctrl↓ + L↓ + chars + L↑ + Ctrl↑`(Chromium omnibox 标准 select-all 快捷键)。
但在 WinUI 3 wrapped Edge Save As 中,**Ctrl+L 不 select-all** — 只 focus。光标停在现有文本末尾,typing appends。

**修复**:在 Ctrl+L 序列后,加一次 **`Ctrl+A`** 强制 select-all,然后 typing 替换选择。

**改动**:`uia_inject.rs::try_send_path_via_sendinput`,新增 4 个 INPUT events(Ctrl↓ + A↓ + A↑ + Ctrl↑),在 Ctrl+L 之后、path typing 之前。

**绝对不动**:
- ❌ 不重新加 Enter(之前已修复 Rule 47:不自动触发)
- ❌ 不动 commit_save_button(已修复 Rule 47:不自动 Invoke Save)
- ❌ 不动 find_navigation_address_bar / is_winui3_wrapped / dedup
- ❌ 不动 NSIS hooks / installer

**等等 — 11 events?** 让我细数。

实际:
- `C:\boost_weasel` (15 chars): 2 (Ctrl+L) + 15 (chars) + 2 (release) = 19 ✓

### 1.2 用户截图证据

"目录可以同步到下载弹窗正确的地址栏了" — H1 work ✅

精确场景:用户在同一个 dialog 里切了 2 次路径,第二次 PUSH 时 address bar 还有第一次 PUSH 的旧路径文本。

### 1.3 Chromium Ctrl+L 行为(为什么在 Save As dialog 上失效)

**Chromium omnibox(URL bar)**:
- Ctrl+L = focus AND select-all(标准行为)

**Chromium WinUI 3 wrapped Save As dialog**:
- "address bar" 实际上是 file name box(1001 Edit)
- Ctrl+L 行为**未定义**(WinUI 3 拦截某些快捷键,Chromium 在 dialog context 下行为不同)
- 实测:只 focus 不 select-all

**精确推断**(高置信度):
```
Ctrl+L 焦点变化:    有(从 dialog tree 切到 file name box)
Ctrl+L select-all:  无(光标停在现有文本末尾)
```

这就是拼接根因。

### 4.3 修复后代码

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        let mut inputs: Vec<INPUT> = Vec::with_capacity(4 + target_path.len() + 4);

        // Step 3: Ctrl down, L down — focus Chromium's address bar.
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));

        // v0.5.1 (2026-10-05 user feedback): Ctrl+L alone does NOT select-all
        // in Edge WinUI 3 Save As dialog (it only focuses). Typing then
        // appends to existing text. Add Ctrl+A to force select-all before typing.
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));

        // Step 3b: Ctrl+A — select all text in current focus (file name box).
        inputs.push(make_key(VK_CONTROL.0, 0));  // Ctrl still down from Step 3
        inputs.push(make_key(0x41, 0));           // A down (VK_A = 0x41)
        inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));   // A up
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0)); // Ctrl up

        // Step 4: type the path char-by-char using KEYEVENTF_UNICODE
        // (replaces the selection from Ctrl+A).
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
        }

        // (No Enter — Rule 47: user wants manual confirmation before save.)
        // (No commit_save_button — Rule 47: user wants manual click.)

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        let total = inputs.len() as u32;
        if n != total {
            warn!(
                "v0.5.1 SendInput: queued {total} events, system accepted only {n}; \
                 foreground-lock likely blocked some events (Mavis D3)"
            );
            return false;
        }
        info!("v0.5.1 SendInput Ctrl+L + Ctrl+A + path dispatched ({total} events, no Enter)");
        true
    }
}
```

**关键变化**:
1. **L release 提前**(`VK_L KEYEVENTF_KEYUP` 在 Ctrl+A 之前)— 让 Ctrl+L focus 完成,然后 Ctrl+A 接管
2. **新增 4 events**:Ctrl(已按着)+ A↓ + A↑ + Ctrl↑
3. **log message 更新**:`(19 events)` → `(Ctrl+L + Ctrl+A + path)` 明确包含 Ctrl+A

**Ctrl 状态机细节**:
- Step 3 末尾:Ctrl↓ + L↓(焦点切到 address bar,但 A 未按)
- Step 3b 起始:L↑(释放 L,Ctrl 仍按)+ Ctrl(仍按)+ A↓ + A↑ + Ctrl↑
- 这正确:Chromium Ctrl+L + Ctrl+A 都需要 Ctrl 持续按下
