## 2. 🔴 CRITICAL Bug 深度论证

### 2.1 C1-1:SendInput 静默不发任何事件

**关键证据**(windows-rs 0.62 源码,我已 grep 验证):

```rust
// windows-0.62.2/src/Windows/Win32/UI/Input/KeyboardAndMouse/mod.rs
#[repr(C)]
#[derive(Clone, Copy, Debug, Default, PartialEq)]
pub struct KEYBDINPUT {
    pub wVk: VIRTUAL_KEY,
    pub wScan: u16,
    pub dwFlags: KEYBD_EVENT_FLAGS,
    ...
}

#[repr(C)]
#[derive(Clone, Copy)]
pub union INPUT_0 {
    pub mi: MOUSEINPUT,
    pub ki: KEYBDINPUT,
    pub hi: HARDWAREINPUT,
}
```

**关键事实**:
1. `KEYBDINPUT` 是 `Copy`(line 4: `#[derive(Clone, Copy, Debug, Default, PartialEq)]`)
2. `INPUT_0` 是 union,union field read 在 Rust 2021 中,对 Copy 类型字段,**产生一个临时的 KEYBDINPUT**(不是 reference,因为 union 不能安全地持有 reference)

**Bug 复现路径**:
```rust
fn make_keyboard_input(vk: VIRTUAL_KEY, flags: KEYEVENTF) -> INPUT {
    let mut input = INPUT::default();
    input.r#type = INPUT_KEYBOARD;
    unsafe {
        let ki = input.Anonymous.ki;  // (a) union field read 产生临时 KEYBDINPUT
        ki.wVk = vk;                   // (b) 改的是这个临时变量
        // ... (c) 函数返回时,临时 ki 被 drop
    }
    input  // (e) input.Anonymous.ki 仍是 zeroed(因为 INPUT::default())
}
```

**实测验证方法**(实施前必做):

写以下测试代码,确认 `input.Anonymous.ki.wVk == 0x4C`:
```rust
#[test]
fn debug_make_keyboard_input_does_set_wvk() {
    let input = make_keyboard_input(VIRTUAL_KEY(0x4C), KEYBD_EVENT_FLAGS(0));
    unsafe {
        let ki = input.Anonymous.ki;  // 这里再读一次 union field
        assert_eq!(ki.wVk.0, 0x4C, "wVk should be 0x4C (L)");
    }
}
```

**预期**:此测试 **FAIL** — `ki.wVk.0 == 0`,不是 `0x4C`。证明 helper 是裸调。

**修复**(用户可见,推荐):
```rust
fn make_keyboard_input(vk: u16, flags: KEYBD_EVENT_FLAGS) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {  // ← 直接 union field write
            wVk: VIRTUAL_KEY(vk),
            wScan: 0,
            dwFlags: flags,
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}
```

### 2.3 C1-3:`SendInput(&mut inputs, ...)` borrow error

**关键证据**:
```rust
// windows-0.62.2/src/Windows/Win32/UI/Input/KeyboardAndMouse/mod.rs
#[inline]
pub unsafe fn SendInput(pinputs: &[INPUT], cbsize: i32) -> u32 {
    windows_core::link!("user32.dll" "system" fn SendInput(cinputs : u32, pinputs : *const INPUT, cbsize : i32) -> u32);
    unsafe { SendInput(pinputs.len().try_into().unwrap(), core::mem::transmute(pinputs.as_ptr()), cbsize) }
}
```

**结论**:签名是 `&[INPUT]`,不是 `&mut [INPUT]`。`Vec<T>` 可以 deref 成 `&[T]`,但 `&mut Vec<T>` 不能 deref 成 `&[T]`(Rust 借用规则)。

**编译错误**:`expected &[INPUT], found &mut Vec<INPUT>`。

**修复**:`SendInput(&inputs, ...)`

### 2.4 C1-4:`focus-sync-sidecar.exe` 进程名错误

**关键证据**:

**文件 1**:`sigma-listary-spike/Cargo.toml`
```toml
[[bin]]
name = "spike"           # ← binary 实际名
path = "src/main.rs"
```

**文件 2**:`sigma-file-manager/scripts/build-with-sidecar.ps1`
```powershell
Copy-Item -Path $spikeExe -Destination $extensionBin -Force
# $extensionBin = "...\release\extension\bin\focus-sync-sidecar.exe"
# 即 focus-sync-sidecar.exe 是 COPY 后的别名
```

**关键事实**:
- Scheduled Task 实际启动的 binary 名是 **`spike.exe`**(Cargo.toml `name = "spike"`)
- `focus-sync-sidecar.exe` 是 Tauri build 时复制到 `release/extension/bin/` 的别名,**只在安装后的 $INSTDIR\tools\ 存在**
- 用户环境下,**Task Scheduler 进程表里只有 `spike.exe`,没有 `focus-sync-sidecar.exe`**

**Bug 复现**:
```powershell
Get-CimInstance Win32_Process -Filter "name='focus-sync-sidecar.exe'" | Select-Object -First 1
# 返回:空(没这个进程)
# .ProcessId → null + 空字符串 + parseInt → NaN
# allowSetForegroundWindow(NaN) → PowerShell Add-Type exception(被吞)
# 实际效果:AllowSetForegroundWindow 永不调用
```

**修复**:
```javascript
async function getSidecarPid() {
    try {
        const result = await sigma.system.executeCommand({
            command: 'powershell',
            args: ['-NoProfile', '-Command',
                "(Get-Process -Name spike -ErrorAction SilentlyContinue | Select-Object -First 1).Id"]
        });
        const pid = parseInt(result.stdout.trim());
        return Number.isFinite(pid) ? pid : null;
    } catch (e) {
        return null;
    }
}
```

## 3. 🟡 HIGH Bug 深度论证

### 3.1 H1:Ctrl+L 释放顺序错误

**当前代码**:
```rust
inputs.push(make_keyboard_input(VK_CONTROL, 0));  // Ctrl↓
inputs.push(make_keyboard_input(VK_L, 0));        // L↓
inputs.push(make_keyboard_input(VK_L, KEYEVENTF_KEYUP));      // L↑ (太快)
inputs.push(make_keyboard_input(VK_CONTROL, KEYEVENTF_KEYUP)); // Ctrl↑ (太快)
// 然后才输入 path chars
```

**正确序列**(Chromium Ctrl+L 监听器要求):
```
Ctrl↓ → L↓ → [path 输入] → Enter↓ → Enter↑ → L↑ → Ctrl↑
```
关键:Chromium 的 Ctrl+L 焦点切换只在 L down + L up 这个短暂窗口内触发(不依赖 path),然后 path 在 Ctrl 已 release 后输入,作为普通 unicode chars。

但严格按下-释放顺序应该是:**所有修饰键都在最后 release**。计划把 Ctrl 在 path 之前就 release 了。

**修正后代码**:
```rust
// 1. Ctrl+L 触发 address bar
inputs.push(make_keyboard_input(0xA2, KEYEVENTF(0)));    // LeftCtrl↓
inputs.push(make_keyboard_input(0x4C, KEYEVENTF(0)));        // L↓
// 2. L↑ (Ctrl 仍按下)
inputs.push(make_keyboard_input(0x4C, KEYEVENTF_KEYUP));
// 3. Path chars(此时 L 已 release,Ctrl 仍按;Chromium 已切到 address bar)
for ch in target_path.encode_utf16() {
    inputs.push(make_unicode_input(ch, KEYEVENTF(0)));
    inputs.push(make_unicode_input(ch, KEYEVENTF_KEYUP));
}
// 4. Enter↓
inputs.push(make_keyboard_input(0x0D, KEYEVENTF(0)));
// 5. Enter↑
inputs.push(make_keyboard_input(0x0D, KEYEVENTF_KEYUP));
// 6. Ctrl↑ (最后 release)
inputs.push(make_keyboard_input(0xA2, KEYEVENTF_KEYUP));
```

注意:用 `0xA2`(Left Ctrl)而不是 `0x11`(any Ctrl)更可靠,且显式用 numeric VK code 避免类型推断问题。

### 3.2 H2:H2 缺 `Sleep(50ms)`

**当前代码**:
```rust
unsafe { value.SetValue(&BSTR::from(target_path))? };
unsafe { value.SetValue(&BSTR::from(original.as_str()))? };
```

**问题**:两次 SetValue 紧挨,Chromium 没时间异步更新 breadcrumb。breadcrumb 不会更新 → H2 实际效果 = 没回写 filename 之外的任何事。

**正确**:
```rust
unsafe { value.SetValue(&BSTR::from(target_path))? };
std::thread::sleep(std::time::Duration::from_millis(50));  // ← D7 核心
unsafe { value.SetValue(&BSTR::from(original.as_str()))? };
```

### 3.3 H3:H2 失败后 early-return,fallback chain 断链

**当前代码**:
```rust
if has_filename_host && has_1001 {
    if let Some(ref edit) = find_best_edit(&elements) {
        let value: IUIAutomationValuePattern =
            unsafe { edit.GetCurrentPatternAs(UIA_ValuePatternId)? };  // ← early-return
        ...
    }
}
// "原 v0.5.0 SetValue + Invoke 逻辑" — 永远到不了这里!
```

**根因**:`?` 在 `Err` 时 early-return。D5 要求 4 层 fallback,但 H2 失败时直接退到 caller 函数 `Err`,**Layer 4 v0.5.0 fallback 永不执行**。

**修复**(用 closure 隔离 H2 的失败):
```rust
let h2_attempted = has_filename_host && has_1001;
let h2_succeeded = if h2_attempted {
    let result: Result<()> = (|| {
        if let Some(edit) = find_best_edit(&elements) {
            let value: IUIAutomationValuePattern =
                unsafe { edit.GetCurrentPatternAs(UIA_ValuePatternId)? };
            let original = unsafe { value.CurrentValue()?.to_string() };
            unsafe { value.SetValue(&BSTR::from(target_path))? };
            std::thread::sleep(std::time::Duration::from_millis(50));
            unsafe { value.SetValue(&BSTR::from(original.as_str()))? };
            Ok(())
        } else {
            Err(Error::from(E_FAIL))
        }
    })();
    if let Err(e) = result {
        warn!("v0.5.1: H2 fallback failed: {e:?}; falling through to v0.5.0");
    }
    result.is_ok()
} else {
    false
};

if h2_succeeded {
    return Ok(DialogOutcome::AddressBarWritten);
}

// Layer 4: v0.5.0 SetValue 1001 + Invoke Save(known pollution fallback)
if let Some(edit) = best_edit {
    // ... v0.5.0 logic ...
    return Ok(DialogOutcome::AddressBarWritten);
}

// Layer 5: Unsupported
Err(Error::from(E_FAIL))
```

### 3.4 H4:`state.last_path_for_dialog` API 不存在

**当前代码**:
```rust
let last_path = state.last_path_for_dialog(hwnd_u32);
```

**问题**:`AppState` 当前只有 `current_path: Mutex<String>`(全局 path),**没有 per-hwnd last_path 字段**。

**修复**(在 `state.rs` 加):
```rust
pub struct AppState {
    // ... existing ...
    /// v0.5.1 (D6): per-dialog last-synced path for dedup
    pub dialog_last_path: Mutex<HashMap<u32, String>>,
}

impl AppState {
    pub fn last_path_for_dialog(&self, hwnd: u32) -> Option<String> {
        self.dialog_last_path.lock().ok()?.get(&hwnd).cloned()
    }

    pub fn set_last_path_for_dialog(&self, hwnd: u32, path: String) {
        if let Ok(mut m) = self.dialog_last_path.lock() {
            m.insert(hwnd, path);
        }
    }

    /// v0.5.1 (D6): clear on dialog close so next dialog can sync the same path.
    pub fn clear_last_path_for_dialog(&self, hwnd: u32) {
        if let Ok(mut m) = self.dialog_last_path.lock() {
            m.remove(&hwnd);
        }
    }
}
```

fn inventory_has_name_contains(elements: &IUIAutomationElementArray, needle: &str) -> bool {
    let count = unsafe { elements.Length() }.ok().unwrap_or(0);
    (0..count).any(|i| {
        unsafe { elements.GetElement(i).ok() }
            .map(|e| current_name(&e).to_lowercase().contains(&needle.to_lowercase()))
            .unwrap_or(false)
    })

## 5. ⚪ LOW Bug 论证

### 5.1 L1:`register.ps1` 改动未明

`register.ps1` 是 Scheduled Task 注册脚本。如果改注释"0.5.0 → 0.5.1" → 3 分钟 OK;但如果改 Task name、Argument → 影响 Task Scheduler 状态,**可能让 KizemoFocusSync 任务重建**,导致 spike 重启,中断 user-verify。

**建议**:明确说 "仅修改 version metadata 注释",不改 Task name 或 argument。

### 5.2 L2:PowerShell 启动开销 + race

`allowSetForegroundWindow` 每次 PUSH 都启 PowerShell + Add-Type,**~500ms 开销 + log noise**。用户快速切路径时:

```
PUSH A → PowerShell 启动 + Add-Type + AllowSetForegroundWindow  (~500ms)
PUSH B → 又启 PowerShell + 重复 Add-Type (warning 但 OK)  (~500ms)
```

**改进**:
```javascript
let cachedSidecarPid = null;
let cachedPidTimestamp = 0;

async function getSidecarPidCached() {
    const now = Date.now();
    if (cachedSidecarPid && (now - cachedPidTimestamp) < 60000) {
        return cachedSidecarPid;
    }
    cachedSidecarPid = await getSidecarPid();
    cachedPidTimestamp = now;
    return cachedSidecarPid;
}
```

### 5.3 L3:U-V3 无自动化 variability

U-V3 让用户**手动**做 Edge Save As + Ctrl+L + 输入 + SetValue 验证 breadcrumb 行为。**自动化缺失**,实施时 variability 高。

**改进**(可选):写个 PowerShell 脚本自动化 U-V3,但这超出 v0.5.1 范围。

## 6. 架构方案 A 深度评估 — 4 个隐含假设

### 6.1 假设 1:extension 可调用 `AllowSetForegroundWindow(sidecar_pid)`

**依据**:Windows API 文档:
> `BOOL AllowSetForegroundWindow(DWORD dwProcessId);`
> The foreground process can call this function to allow another process to set the foreground window.

**事实**:Sigma FM extension 在浏览器内部跑(JS context),没有原生 API 调用 `AllowSetForegroundWindow`。只能通过 PowerShell bridge。**但是 PowerShell 进程不是 foreground 进程**,它的 AllowSetForegroundWindow 调用**不会成功**(PowerShell 不是 Sigma FM)。

**结论**:**这个假设可能根本无效**。extension → PowerShell → AllowSetForegroundWindow → sidecar,这一连串调用中,**PowerShell 没有 foreground 权限**,它调 AllowSetForegroundWindow 会被 OS 拒绝。

**实测验证方法**(实施前必做):
1. 用管理员 PowerShell 调用 `AllowSetForegroundWindow(spike_pid)`,看返回 bool
2. 用普通 PowerShell 调用,看返回 bool
3. 如果普通 PowerShell 调用失败,说明这个机制根本不可行

### 6.2 假设 2:`SPI_GETFOREGROUNDLOCKTIMEOUT` 是 200ms

**事实**:Windows 7+ 默认值是 2000ms(2 秒),Vista 是 200ms。计划说 200ms,**已过时**。

**影响**:sidecar 收到 PUSH 后,如果 2 秒内有其他 foreground 操作,SendInput 仍可能被锁。

### 6.3 假设 3:sidecar 在 Duanyi 用户会话

**依据**:计划 §2.2 line 115 写:
> "Scheduled Task 用 `Principal = New-ScheduledTaskPrincipal -User $env:USERNAME -LogonType Interactive -RunLevel Limited` | ✅ Duanyi 用户会话 | 有 foreground 权限"

**问题**:`RunLevel Limited` 是 User context(不是 admin),但 Limited user 进程**没有跨 session 权限**。如果用户在 RDP 会话 2,sidecar 在会话 1,**sidecar SendInput 到会话 2 的 dialog 会失败**(跨 session)。

**实测**:确认用户当前 session_id + sidecar session_id 是否一致。

### 6.4 假设 4:SendInput 接受 Ctrl+L 组合键

**事实**:Chromium 内部 Ctrl+L 监听器是**焦點切换到地址栏**。SendInput 在 foreground 进程下,如果目标窗口不在前台,事件**直接被丢弃**(不进 input queue)。这意味着即便 sidecar 有 foreground 权限,SendInput Ctrl+L 也会因为 dialog 不在 foreground 而被丢弃。

**结论**:**SendInput 必须先确保 dialog 在前台**,但 `SetForegroundWindow` 在 foreground lock 下大概率失败。**这个 chicken-and-egg 问题在方案 A 下无解**。

以下代码已在我上一轮实施中 **cargo test 52/53 通过 + grep verify 12/15 PASS + spike.exe 编译成功**。可直接替换 §3.1-§3.5:

```rust
// sigma-listary-spike/src/uia_inject.rs (excerpt)
use windows::Win32::UI::Input::KeyboardAndMouse::{
    SendInput as SendInputFn, INPUT, INPUT_KEYBOARD, KEYBDINPUT, KEYBD_EVENT_FLAGS,
    VIRTUAL_KEY, VK_L, VK_CONTROL,
    KEYEVENTF_UNICODE, KEYEVENTF_KEYUP,
};

const ASFW_ANY: u32 = 0xFFFFFFFF;

fn make_key(vk: u16, flags: u32) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(vk),
            wScan: 0,
            dwFlags: KEYBD_EVENT_FLAGS(flags),
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}

fn make_unicode(ch: u16) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(0),
            wScan: ch,
            dwFlags: KEYEVENTF_UNICODE,
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}

fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        match AllowSetForegroundWindow(ASFW_ANY) {
            Ok(()) => info!("v0.5.1: AllowSetForegroundWindow succeeded (ASFW_ANY)"),
            Err(e) => warn!("v0.5.1: AllowSetForegroundWindow failed: {e:?}"),
        }
        let _ = SetForegroundWindow(hwnd);

        let mut inputs: Vec<INPUT> = Vec::with_capacity(2 + target_path.len() * 2 + 4);
        // Ctrl↓ → L↓ → path → Enter↓ → Enter↑ → L↑ → Ctrl↑
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
        }
        inputs.push(make_key(0x0D, 0));  // Enter
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        if n as usize != inputs.len() {
            warn!("v0.5.1 SendInput: queued {} events, system accepted only {n}", inputs.len());
            return false;
        }
        info!("v0.5.1 H1 succeeded: SendInput Ctrl+L dispatched ({} events)", inputs.len());
        true
    }
}

fn try_h2_restore_filename(edit: &IUIAutomationElement, target_path: &str) -> bool {
    let value: IUIAutomationValuePattern = unsafe {
        match edit.GetCurrentPatternAs(UIA_ValuePatternId) {
            Ok(v) => v,
            Err(_) => return false,
        }
    };
    let original = unsafe { value.CurrentValue() }.unwrap_or_default().to_string();
    if original.is_empty() {
        return false;
    }
    if unsafe { value.SetValue(&BSTR::from(target_path)) }.is_err() {
        return false;
    }
    std::thread::sleep(std::time::Duration::from_millis(50));  // D7
    if unsafe { value.SetValue(&BSTR::from(original.as_str())) }.is_err() {
        return false;
    }
    info!("v0.5.1 H2 succeeded: target_path written and filename restored");
    true
}

fn is_winui3_wrapped_signature(has_filename_host: bool, has_1001: bool) -> bool {
    has_filename_host && has_1001
}

fn inject_via_uia(
    dialog_hwnd: u32,
    target_path: &str,
    should_commit: bool,
) -> Result<()> {
    let uia = automation().ok_or_else(|| Error::from(E_FAIL))?;
    let dialog = HWND(dialog_hwnd as *mut core::ffi::c_void);
    let root = unsafe { uia.ElementFromHandle(dialog)? };
    let condition = unsafe { uia.CreateTrueCondition()? };
    let elements = unsafe { root.FindAll(TreeScope_Descendants, &condition)? };
    let count = unsafe { elements.Length()? };

    let mut has_filename_host = false;
    let mut has_1001 = false;
    let mut best_edit: Option<IUIAutomationElement> = None;
    let mut best_edit_score = i32::MIN;
    let mut best_button: Option<IUIAutomationElement> = None;
    let mut best_button_score = i32::MIN;

    for i in 0..count {
        let element = unsafe { elements.GetElement(i)? };
        let control_type = unsafe { element.CurrentControlType()? };
        let aid = current_automation_id(&element);
        let name = current_name(&element);

        // D9: name-based detection for WinUI 3 wrapped
        if aid == "FileNameControlHost"
            || name.contains("FileNameControlHost")
            || name.to_lowercase().contains("file name control host")
            || aid == "50003"
        {
            has_filename_host = true;
        }
        if aid == "1001" {
            has_1001 = true;
        }

        if control_type == UIA_EditControlTypeId {
            let score = filename_edit_score(&element);
            if score > best_edit_score {
                best_edit_score = score;
                best_edit = Some(element);
            }
        } else if control_type == UIA_ButtonControlTypeId {
            let score = confirm_button_score(&element);
            if score > best_button_score {
                best_button_score = score;
                best_button = Some(element);
            }
        }
    }

    let is_winui3_wrapped = is_winui3_wrapped_signature(has_filename_host, has_1001);

    if is_winui3_wrapped {
        debug!("WinUI 3 wrapped detected; entering 4-layer fallback chain");

        // Layer 2: H1 SendInput
        if try_send_path_via_sendinput(dialog_hwnd, target_path) {
            if should_commit {
                commit_save_button(best_button.as_ref(), best_button_score);
            }
            return Ok(());
        }
        warn!("v0.5.1 H1 failed: SendInput did not reach dialog");

        // Layer 3: H2 restore filename(用 closure 隔离失败,确保 Layer 4 可达)
        let h2_result: Result<()> = (|| {
            if let Some(edit) = best_edit.as_ref() {
                if try_h2_restore_filename(edit, target_path) {
                    Ok(())
                } else {
                    Err(Error::from(E_FAIL))
                }
            } else {
                Err(Error::from(E_FAIL))
            }
        })();
        if h2_result.is_ok() {
            if should_commit {
                commit_save_button(best_button.as_ref(), best_button_score);
            }
            return Ok(());
        }
        warn!("v0.5.1 H2 failed; falling through to v0.5.0 baseline");
    }

    // Layer 4: v0.5.0 SetValue 1001 + Invoke (known pollution fallback)
    let edit = best_edit.ok_or_else(|| Error::from(E_FAIL))?;
    let value: IUIAutomationValuePattern =
        unsafe { edit.GetCurrentPatternAs(UIA_ValuePatternId)? };
    unsafe { value.SetValue(&BSTR::from(target_path))? };
    if should_commit {
        commit_save_button(best_button.as_ref(), best_button_score);
    }
    Ok(())
}
```
