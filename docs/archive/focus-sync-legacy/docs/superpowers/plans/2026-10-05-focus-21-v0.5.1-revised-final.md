## 2. 关键架构问题(D3 深度分析)

### 2.1 sidecar SendInput 在 Vista+ 的限制

**SendInput 需要两个条件**(Windows API 文档):
1. **Active foreground**:调用 SendInput 的进程必须在过去 ~200ms 内是 foreground 进程
2. **Foreground lock timeout (SPI_GETFOREGROUNDLOCKTIMEOUT)**:200ms 内其他进程无法强制前台

**sidecar 当前状态**:
- Scheduled Task AtLogOn 启动,运行在 Duanyi 用户会话
- `--service` flag 触发,无 Console 显示
- **没有 foreground 历史**(用户前台是 Sigma FM,不是 sidecar)

**SendInput 失败的两种路径**:
1. **sidecar 调用 SetForegroundWindow(dialog)** → Windows 拒绝(无 foreground 历史)
2. **sidecar 调用 AllowSetForegroundWindow(spike_pid) ** → 只能让自己前台,**不能前台 dialog**
3. **sidecar 调用 SendInput(...)** → 事件发到 nowhere(无 active foreground)

### 2.2 实际可能性(实测前不确定)

| 因素 | 实测预期 | 影响 |
|---|---|---|
| Sigma FM extension 在前台 | ✅ 用户使用 Sigma FM 时 | extension 可调用 AllowSetForegroundWindow(sidecar_pid) |
| extension 调用时序 | ❓ | 必须 BEFORE SendInput,不能延迟 |
| Scheduled Task 用 `Principal = New-ScheduledTaskPrincipal -User $env:USERNAME -LogonType Interactive -RunLevel Limited` | ✅ Duanyi 用户会话 | 有 foreground 权限 |
| `--service` flag 不影响 foreground 权限 | ✅ | sidecar 仍在 Duanyi 会话 |

**结论**:sidecar SendInput **理论上可行**(如果 Sigma FM extension 在 PUSH 时先调 AllowSetForegroundWindow),但 **实际行为需要实测验证**。

### 2.3 决策树

```
SendInput 在哪个进程执行?
│
├── A. sidecar SendInput(默认路径)
│   ├── 优点:架构简单,无需改动 extension manifest
│   ├── 缺点:Vista+ foreground 限制可能拒
│   ├── 缓解:extension PUSH 前调 AllowSetForegroundWindow(sidecar_pid)
│   └── 实测:在 Edge WinUI 3 Save As 上验证
│
└── B. extension SendInput(架构改动)
    ├── 优点:extension 已在 foreground,SendInput 100% work
    ├── 缺点:需要 extension manifest "input" 权限 + 新 IPC
    ├── 架构:sidecar 不再 SendInput,只做 PUSH 接收 + UIA 检测
    └── 实施:扩展 ~2 周,超出 v0.5.1 范围
```

**v0.5.1 范围**:**先实施 A(sidecar SendInput)+ extension 调 AllowSetForegroundWindow 配合 + 多层 fallback**。如果实测失败,再考虑 B 架构改动。

## 3. v0.5.1 实施代码(完整,无占位符)

### 3.1 SendInput 主函数(D1 ASFW_ANY + D2 helper 完整)

```rust
// uia_inject.rs 新增(在 inject_folder_path 之前)

/// v0.5.1: 通过 SendInput 把路径键入到 Chromium 内部地址栏。
///
/// 适用 WinUI 3 wrapped Edge Save As dialog(1001 Edit 是双角色):
///   1. AllowSetForegroundWindow(spike_pid) — 必须由 Sigma FM extension 在 PUSH 前调
///   2. SetForegroundWindow(dialog) — 把 dialog 拉到前台
///   3. SendInput Ctrl+L — Chromium 聚焦地址栏
///   4. SendInput path UTF-16 chars — 输入路径
///   5. SendInput Enter — 导航
///
/// 完全不碰 1001 Edit → filename 不污染。
///
/// Mavis D1 修正:ASFW_ANY 必须是 0xFFFFFFFF,不是 0x00000001
/// (windows crate 的 ASFW_ANY 常量值)。
const ASFW_ANY: u32 = 0xFFFFFFFF;

fn send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    use windows::Win32::UI::Input::KeyboardAndMouse::{
        SendInput, INPUT, INPUT_KEYBOARD, KEYEVENTF, KEYEVENTF_KEYUP,
        KEYBD_EVENTF_UNICODE, VIRTUAL_KEY, VK_CONTROL, VK_L, VK_RETURN,
    };
    use windows::Win32::UI::WindowsAndMessaging::{
        AllowSetForegroundWindow, SetForegroundWindow,
    };
    use windows::Win32::Foundation::HWND;

    unsafe {
        let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);

        // Step 1: 尝试让 sidecar 自己获 foreground(可能 fail — Vista+ 限制)
        let _ = AllowSetForegroundWindow(ASFW_ANY);  // D1 修正
        if SetForegroundWindow(hwnd).is_err() {
            warn!("SetForegroundWindow failed; dialog may not receive SendInput");
            // 不直接 return false — 仍尝试 SendInput,有时 Win 会接受
        }

        // Step 2: 构造 INPUT 序列
        let mut inputs: Vec<INPUT> = Vec::with_capacity(4 + target_path.len() + 4);

        // Ctrl 按下
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_CONTROL.0),
            KEYEVENTF(0),
        ));
        // L 按下
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_L.0),
            KEYEVENTF(0),
        ));
        // L 释放
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_L.0),
            KEYEVENTF_KEYUP,
        ));
        // Ctrl 释放
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_CONTROL.0),
            KEYEVENTF_KEYUP,
        ));

        // Path 字符(用 KEYBD_EVENTF_UNICODE,UTF-16 chars)
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode_input(ch, KEYEVENTF(0)));
            inputs.push(make_unicode_input(ch, KEYEVENTF_KEYUP));
        }

        // Enter 按下+释放
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_RETURN.0),
            KEYEVENTF(0),
        ));
        inputs.push(make_keyboard_input(
            VIRTUAL_KEY(VK_RETURN.0),
            KEYEVENTF_KEYUP,
        ));

        // Step 3: SendInput
        let n = SendInput(&mut inputs, std::mem::size_of::<INPUT>() as i32);
        if n as usize != inputs.len() {
            warn!("SendInput only sent {n} of {} inputs", inputs.len());
            return false;
        }
        info!("v0.5.1: SendInput Ctrl+L + path + Enter succeeded");
        true
    }
}

/// D2 完整实现:构造普通键盘 INPUT(virtual key code)
fn make_keyboard_input(vk: VIRTUAL_KEY, flags: KEYEVENTF) -> INPUT {
    let mut input = INPUT::default();
    input.r#type = INPUT_KEYBOARD;
    unsafe {
        let ki = input.Anonymous.ki;
        ki.wVk = vk;
        ki.wScan = 0;
        ki.dwFlags = flags.0;
        ki.time = 0;
        ki.dwExtraInfo = 0;
        // Anonymous union already zeroed by INPUT::default()
    }
    input
}

/// D2 完整实现:构造 Unicode 键盘 INPUT(UTF-16 char)
fn make_unicode_input(ch: u16, flags: KEYEVENTF) -> INPUT {
    let mut input = INPUT::default();
    input.r#type = INPUT_KEYBOARD;
    unsafe {
        let ki = input.Anonymous.ki;
        ki.wVk = VIRTUAL_KEY(0);
        ki.wScan = ch;
        ki.dwFlags = (flags.0 | KEYBD_EVENTF_UNICODE.0) as u32;
        ki.time = 0;
        ki.dwExtraInfo = 0;
    }
    input
}
```

async function getSidecarPid() {
    try {
        const result = await sigma.system.executeCommand({
            command: 'powershell',
            args: ['-NoProfile', '-Command',

            command: 'powershell',

                `$code = @"
using System;
using System.Runtime.InteropServices;
public class FG {
    [DllImport("user32.dll")]
    public static extern bool AllowSetForegroundWindow(uint pid);
}
"@
Add-Type $code
[FG]::AllowSetForegroundWindow(${pid})`]
        });
    } catch (e) {
        console.warn('allowSetForegroundWindow failed:', e);
    }
}

### 4.2 为什么 extension 必须参与

**架构原因**:
- Sigma FM extension 是用户当前 focus 的 app,**它有 foreground 权限**
- extension 调 `AllowSetForegroundWindow(sidecar_pid)` → 给 sidecar 几秒内"前台权限"
- sidecar 在这几秒内 SendInput → 成功(即使没 SetForegroundWindow)
- 这是 Windows 标准的"前台权限传递"模式

**如果不做此步骤**(只有 sidecar 自己):
- sidecar SendInput 失败概率高(Vista+ foreground lock)
- 即使 `AllowSetForegroundWindow(spike_pid)` 让自己前台,也只能前台 sidecar 自己的窗口
- **SendInput 仍可能失败**

## 5. 多层 fallback chain(D5)

```
Edge WinUI 3 wrapped Save As:
  Layer 1: COM IFileDialog::SetFolder                  ← round 19f,Win32 dialog work
  Layer 2: SendInput Ctrl+L + path + Enter              ← v0.5.1 新增(需要 extension 配合 AllowSetForegroundWindow)
  Layer 3: H2 fallback (SetValue target → SetValue original)  ← D4 必须前置 verify
  Layer 4: v0.5.0 Sep 27 SetValue + Invoke              ← 已 ship, fallback
  Layer 5: Return Unsupported + 通知                    ← 最终兜底

每层失败 → 下一层
每层成功 → return Ok(AddressBarWritten) + 不 Invoke Save(让用户手动)
```

**每层之间的检测**:
- Layer 1 → Layer 2: COM `AccessibleObjectFromWindow` 返回错误
- Layer 2 → Layer 3: SendInput 返回值 < inputs.len()
- Layer 3 → Layer 4: H2 未前置 verify(可能回退 breadcrumb)
- Layer 4 → Layer 5: SetValue 失败或 Invoke 失败
