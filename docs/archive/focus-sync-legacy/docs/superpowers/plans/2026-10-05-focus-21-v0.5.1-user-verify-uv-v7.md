## U-V1:Edge WinUI 3,单次 PUSH `C:\evid` 期望保持 filename

### 操作步骤

1. 启动 v0.5.1 spike.exe(scheduled task 或 `--service` flag)
2. 在 Edge Modern 浏览器按 Ctrl+S 打开 Save As dialog
3. filename 字段输入:`WeavePage_3.0.0_x64-setup (1).exe`
4. breadcrumb 此时是默认(可能是 `此电脑 > Downloads`)
5. 在 Sigma FM 主窗口切到 `C:\evid` 路径
6. **观察 Edge Save As dialog**

### 期望结果(用户核心诉求)

| 元素 | 期望 |
|---|---|
| **filename 字段** | `WeavePage_3.0.0_x64-setup (1).exe`(**保持原始**) |
| **breadcrumb** | `此电脑 > Win (C:) > evid`(导航成功) |
| **user 感知** | "dialog 跳转了,但 filename 没被改" |

### 实际可能的失败模式

| 现象 | 根因 | 验证方式 |
|---|---|---|
| filename 仍被改成 `C:\evid` | H1 SendInput 失败 + H2 失败 → fallback v0.5.0 | 看 spike.log,SendInput 数量 |
| breadcrumb 没动 | SendInput 完全失败 + SetValue 失败 | 看 dialog 实际状态 |
| filename 和 breadcrumb 都对 | H1 或 H2 成功 | 成功 |

### 验证日志路径

`C:\Users\Duanyi\AppData\Local\kizemo\focus-sync\logs\spike.log.2026-10-05`

关键日志条目:
```
[INFO] Injection starts: hwnd=... target='C:\evid' should_commit=true
[INFO] v0.5.1 H1 succeeded: SendInput Ctrl+L navigated the dialog
```

或 fallback 时:
```
[WARN] v0.5.1 H1 failed: SendInput did not reach the dialog
[INFO] v0.5.1 H2 succeeded: target_path written and filename restored
```

## U-V2:Edge WinUI 3,多次 PUSH A→B→A + D6 dedup

### 操作步骤

1. Edge Save As dialog 已开,filename = `WeavePage_3.0.0_x64-setup (1).exe`
2. 用户在 Sigma FM 中点击 folder A → push A
3. 用户在 Sigma FM 中点击 folder B → push B
4. 用户在 Sigma FM 中再点击 folder A → push A(重复)

### 期望结果

| 步骤 | breadcrumb | filename | 触发 |
|---|---|---|---|
| 初始 | (默认) | 原始 | 无 |
| PUSH A | `A` | 原始 | SendInput Ctrl+L + path |
| PUSH B | `B` | 原始 | SendInput Ctrl+L + path |
| **PUSH A(重复)** | `A` | **原始** | **D6 dedup 应答,无 SendInput** |

### D6 dedup 验证

spike.log 应包含:
```
[INFO] set_path_dedup path=... (unchanged, skipping dialog write loop)
```

### 实际可能的失败模式

| 现象 | 根因 | 验证方式 |
|---|---|---|
| 第 3 次 PUSH 触发 SendInput(用户看到 filename 被清空)| D6 dedup 没工作 | 看 spike.log 是否有 "set_path_dedup" |
| breadcrumb 切到 A → B → A | 正常 | 正常 |

## U-V6:Chromium 41477

### 操作步骤

1. Chrome 浏览器打开下载对话框(右键 → Save link as)
2. 注意:**Chromium 41477 Save As 与 WinUI 3 wrapped 不同**,41477 是单独的 address bar
3. filename 字段输入:`file.zip`
4. 在 Sigma FM 切到 `E:\backups`

### 期望结果

| 元素 | 期望 |
|---|---|
| **filename 字段** | `file.zip`(可能短暂被改) |
| **breadcrumb / address bar** | `E:\backups`(导航成功) |
| **触发路径** | Layer 3 UIA SetValue 41477 + Invoke |

### 验证日志

```
[INFO] UIA SetValue OK on automation_id='41477' name='...' target='E:\backups'
```

### WinUI 3 wrapped 与 Chromium 41477 的关键区别

| 维度 | WinUI 3 wrapped (Edge Modern) | Chromium 41477 (Chrome) |
|---|---|---|
| 1001 Edit | 双角色(filename + address bar) | 不存在 |
| FileNameControlHost | 存在 | 不存在 |
| 41477 Edit | 不存在 | 单角色(filename + 接受路径) |
| **SendInput Ctrl+L** | **可能有效** | **无效**(无独立 address bar) |
| **SetValue 行为** | filename 污染 + breadcrumb 自动更新 | 直接接受路径作为 navigation |

**v0.5.1 在 41477 上不进入 SendInput 路径**(D9 检测),直接 Layer 3 SetValue。
