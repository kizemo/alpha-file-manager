## 0. TL;DR(60 秒)

**真正的根因**(Phase 1 调查发现):

WinUI 3 wrapped Edge Save As dialog 的 **1001 Edit**(filename Edit)**同时承担两个角色**:
1. **filename 显示字段**(用户看到的文件名)
2. **address bar 输入**(Chromium 内部逻辑:如果内容像路径,自动更新 breadcrumb)

SetValue 写路径 → WinUI 3 **同时**更新 filename 显示 + breadcrumb → 用户 reject "filename 被改"。

**正确方案**(不是再"改进"v0.5.0,而是**回到正确的方法**):

```
1. SetForegroundWindow(dialog)                  ← 让 dialog 接收键盘输入
2. SendInput Ctrl+L                              ← focus 地址栏(Chromium 标准快捷键)
3. SendInput "C:\evid\WeavePage...exe"           ← 输入完整路径
4. SendInput Enter                               ← 导航
```

**核心**:完全绕开 1001 Edit,通过 SendInput 把路径直接键入到 Chromium 内部地址栏。

## Phase 1: Root Cause Investigation(证据驱动)

### 1.1 错误信息精确分析(sidecar log)

**最新一次真实测试**(2026-10-05 01:30:43, hwnd=788472, target=C:\evid):


**关键解读**:
1. **COM 失败**("not a native IFileDialog") → WinUI 3 wrapper 屏蔽了 IAccessible 接口
2. **UIA SetValue 写到 1001 Edit** → 这是**致命选择**,因为 1001 Edit 在 WinUI 3 中是**双角色**
3. **Injection succeeded** → UIA 层面 SetValue 成功,但**用户看到的是污染**

### 1.2 WinUI 3 wrapped dialog 的内部逻辑(基于 Chromium 实现)

Edge Save As dialog(WinUI 3 wrapped):
- 外层 WinUI 3 容器(只读):breadcrumb、tree view header
- 内层 Chromium Save As(file name box 智能双角色):
  - 用户输入"C:\evid" → Chromium 解析:parent=C:\, filename="evid"
  - 如果 parent 存在 → 导航到 C:\
  - 如果 filename 是已存在的文件夹 → 自动导航到该文件夹
- 结果:C:\evid 路径被 Chromium 当作 "navigate to folder evid under C:\"

**1001 Edit 在 WinUI 3 wrapped 中的双重身份**:
| 角色 | 来源 | 影响 |
|---|---|---|
| Filename 显示 | WinUI 3 Pane `FileNameControlHost`(50003) | 顶部"文件名"标签 |
| Address bar 输入 | Chromium 内部 file name box 智能解析 | breadcrumb 自动更新 |

**SetValue 到 1001 同时触发两个角色**。

## Phase 3: Hypothesis(4 条候选方案)

### Hypothesis 1: SetForegroundWindow + Ctrl+L + 键入路径(SendInput)

**原理**:
1. SetForegroundWindow(dialog) → 把 dialog 拉到前台
2. AllowSetForegroundWindow(spike_pid) → 获取前台权限
3. SendInput Ctrl+L → Chromium 标准快捷键聚焦地址栏
4. SendInput path string → 输入完整路径
5. SendInput Enter → 导航

**理论**:
- 不写 1001 Edit → 不污染 filename
- 用 Chromium 内部 address bar(如果有)→ 只更新 breadcrumb
- 跟用户手动操作一致(用户也是 Ctrl+L → 输入 → Enter)

**风险**:
- SendInput 可能触发反病毒告警
- `SetForegroundWindow` 在 Vista+ 有限制(200ms 锁定)
- Edge WinUI 3 可能不响应 Ctrl+L(需要验证)

**实施难度**:中等。代码 ~50 行,需要 windows crate 的 `SendInput` API + `AllowSetForegroundWindow`。

### Hypothesis 2: 写入后恢复 filename(2 步法)

**原理**:
1. Read filename(原始值 "WeavePage_3.0.0_x64-setup (1).exe")
2. SetValue "C:\evid" 到 1001 Edit → Chromium 更新 breadcrumb
3. 立即 SetValue 原始 filename 回去 → filename 字段恢复

**理论**:
- breadcrumb 已经更新(Chromium 缓存,不会因 filename 回写而回退)
- filename 字段最终显示原始值
- 不需要 SendInput

**风险**:
- 用户可能在中间看到"C:\evid"(2 个 SetValue 之间的几十毫秒)
- WinUI 3 可能每次 SetValue 都触发 re-render,引起闪烁
- Chromium 是否在第二次 SetValue 后回退 breadcrumb,需要验证

**实施难度**:简单。代码 ~15 行,只需保存原值再回写。

### Hypothesis 3: 用 41477 自动化 ID(把 Edge WinUI 3 当 Chromium 41477)

**原理**:
- WinUI 3 wrapped Save As **没有** 41477(per inventory dump)
- 但 Edge Chromium Save As **有** 41477
- 误判风险:把 WinUI 3 wrapped 当成 Chromium 41477 → 失败

**风险**:v0.4.0 已尝试,失败。

**结论**:**不做此假设**。WinUI 3 wrapped 没有 41477,必须另寻路径。

### Hypothesis 4: 点击 breadcrumb segments(树状导航)

**原理**:
1. Find breadcrumb container
2. Click "此电脑" → 不变(已在根)
3. Click "Win (C:)" → 导航到 C:\
4. Click "evid" → 导航到 C:\evid(但 evid 是 C:\ 的子目录,可能在 file list 里,不在 breadcrumb)

**限制**:
- breadcrumb segments 是"祖先路径",不能跳到 sibling
- 想从 C:\downloads 跳到 C:\evid,需要先点击 C:\(回到根),再点 file list 里的 evid

**实施复杂度**:高(需要 tree view 导航,基于 inventory 的元素)

## Phase 4: 实施方案

### 4.1 推荐方案:Hypothesis 1(SendInput Ctrl+L)

**理由**:
- 最贴近用户手动操作(用户用 Ctrl+L + 输入路径 + Enter)
- 不污染 filename(完全不写 1001 Edit)
- 实施后可扩展(支持 Chromium 所有 variants)

**改动清单**:

1. **uia_inject.rs** 新增函数 `send_path_via_sendinput(dialog_hwnd, target_path)`:
   ```rust
   /// focus-21 v0.5.1: 通过 SendInput 键入路径到 Chromium 地址栏
   ///
   /// 适用 WinUI 3 wrapped Edge Save As:
   ///   1. SetForegroundWindow(dialog) → 前台
   ///   2. AllowSetForegroundWindow(spike_pid) → 前台权限
   ///   3. SendInput Ctrl+L → Chromium 聚焦地址栏
   ///   4. SendInput path + Enter → 导航
   ///
   /// 不污染 filename Edit(完全绕开 1001 Edit)。
   fn send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
       unsafe {
           use windows::Win32::UI::Input::KeyboardAndMouse::{
               SendInput, INPUT, INPUT_KEYBOARD, KEYBD_EVENTF, VK_L, VK_RETURN,
               VK_CONTROL, KEYEVENTF_KEYUP,
           };
           use windows::Win32::Foundation::HWND;

           let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);

           // 1. 获取前台权限 + 把 dialog 拉到前台
           let _ = windows::Win32::UI::WindowsAndMessaging::AllowSetForegroundWindow(0x00000001); // ASFW_ANY
           if windows::Win32::UI::WindowsAndMessaging::SetForegroundWindow(hwnd).is_err() {
               warn!("SetForegroundWindow failed; SendInput may not reach dialog");
               return false;
           }

           // 2. SendInput Ctrl+L
           let mut inputs = vec![
               make_key(VK_CONTROL.0, 0),
               make_key(VK_L.0, 0),
           ];
           // 3. SendInput target_path 字符(UTF-16 → VK_PACKET 不行,改用 KEYBD_EVENTF_UNICODE)
           for ch in target_path.encode_utf16() {
               inputs.push(make_unicode(ch));
           }
           inputs.push(make_key(VK_RETURN.0, 0));
           // 释放键
           inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0 as u32));
           inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0 as u32));

           let n = SendInput(&mut inputs, std::mem::size_of::<INPUT>() as i32);
           n as usize == inputs.len()
       }
   }

   fn make_key(vk: u16, flags: u32) -> INPUT { /* ... */ }
   fn make_unicode(ch: u16) -> INPUT { /* KEYBD_EVENTF_UNICODE */ }
   ```

2. **inject_via_uia** 流程调整:
   ```rust
   fn inject_via_uia(dialog_hwnd, target_path, should_commit) -> Result<()> {
       // v0.5.1 新增:WinUI 3 wrapped dialog 用 SendInput(不写 1001 Edit)
   ```

### 4.2 备选方案:Hypothesis 2(写入后恢复 filename)

**适用条件**:Hypothesis 1 实施后 Edge 不响应 Ctrl+L

**改动清单**:

1. **inject_via_uia** 加入 "save original + restore" 模式:
   ```rust
   let edit = best_edit.ok_or_else(|| Error::from(E_FAIL))?;

   // Step 1: 保存原始 filename
   let value = ...;
   let original_filename = value.CurrentValue()?.to_string();

   // Step 2: 写入 target_path(WinUI 3 自动更新 breadcrumb)
   value.SetValue(target_path)?;

   // Step 3: 立即恢复 original filename
   // (Chromium 内部 breadcrumb 已锁定,不因 filename 回写而回退)
   if let Ok(orig) = BSTR::from(original_filename.as_str()).into() {
       value.SetValue(&orig)?;
   }

   Ok(())
   ```

2. **风险**:WinUI 3 Chromium 是否在 filename 回写时也回退 breadcrumb,需要实测验证。
