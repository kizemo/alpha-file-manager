## 1. Mavis 4 处改进采纳

### 1.1 I1 — 删除冗余 Ctrl↓(采纳)

**当前 v0.5.1 初版 §4.3 代码**:
```rust
inputs.push(make_key(VK_CONTROL.0, 0));  // ← (d) 冗余!
inputs.push(make_key(0x41, 0));           // A↓
```

**问题**:注释 "Ctrl still down from Step 3" 但代码又 push Ctrl↓。实际键盘 queue 收到 2 个 Ctrl↓ + 1 个 Ctrl↑,可能触发 WinUI 3 / Chromium Ctrl 状态 edge case。

**修复**:删除 (d) 行。Ctrl 保持按住从 Step 3 到 A↓ 之后。

### 1.2 I3 — KEYEVENTF_UNICODE 加 release(采纳)

**当前 `make_unicode`** 只发 press,不发 release。

**MSDN**:
> "To simulate pressing and releasing a key, send two events. The first event should specify KEYEVENTF_KEYDOWN ... and the second event should specify KEYEVENTF_KEYUP."

**修复**:加 `make_unicode_release`,每个 char 发 press + release。

**Event count 影响**:从 N 变 2N(每 char 2 events)。

### 1.3 I4 — Version bump 0.5.1 → 0.5.2(采纳)

**理由**:
- 修了 v0.5.1 的已知 bug(directory sync 拼接),不算 hotfix
- 让用户清楚知道这是新版本
- 避免 4 位版本号在 Windows 安装包版本检查中的兼容问题

**改动**:
- `http_server.rs`:SPIKE_VERSION `"0.5.1"` → `"0.5.2"`
- `http_server.rs` test 断言:`"version\":\"0.5.1\"` → `"0.5.2\"`
- `index.js`:header + activate log
- `register.ps1`:10 处版本号 + "v0.5.1" 字样
- setup.exe 文件名:`...v0.5.1-setup.exe` → `...v0.5.2-setup.exe`

### 1.4 I2 — Filename 污染 verify(纳入 user-verify)

**Mavis 关注**:Ctrl+A 在 1001 Edit 上会选中 filename,如果 address bar = 1001(filename display 共用),Ctrl+A 后 typing 会**污染 filename**(违反 13 轮 root cause)。

**现状**:
- v0.5.1 已 ship 后,用户实测:filename 不污染(只 breadcrumb 更新)
- 说明 Edge WinUI 3 wrapped 的 address bar 是**独立**于 1001 filename display 的 UIA 元素,或 WinUI 3 内部做了区分

**实施**:不预设结论,**在 user-verify 加实测问题**(§3.4)。

### 1.5 D6 fallback(Mavis 推荐,可选)

**Home + Shift+End 强制选中整个 line**:
- 比 Ctrl+A 更基础(Edit 标准操作),WinUI 3 不太可能截
- 实施复杂(7 events vs Ctrl+A 的 4 events)
- 优先级:**Ctrl+A fail 时才用 D6**

**当前不实施**,留作 Ctrl+A fail 实测后的 fallback。

### 2.2 `uia_inject.rs` 改动

**改动 A**:`try_send_path_via_sendinput`(line 213-258 当前)— 加 Ctrl+A + 移除冗余 Ctrl↓ + log message 更新

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        let mut inputs: Vec<INPUT> =
            Vec::with_capacity(5 + target_path.encode_utf16().count() * 2);

        // Step 3: Ctrl+L — focus Chromium's address bar.
        // In WinUI 3 wrapped Save As, Ctrl+L focuses but does NOT select-all
        // (chromium omnibox default behavior doesn't apply). Typing then
        // appends to existing text → concatenation bug.
        inputs.push(make_key(VK_CONTROL.0, 0));   // Ctrl↓
        inputs.push(make_key(VK_L.0, 0));         // L↓
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0)); // L↑
        // Ctrl is still held from the Ctrl↓ above.

        // v0.5.2 (2026-10-05): add Ctrl+A to force select-all before typing.
        // (Ctrl is still held; do NOT push another Ctrl↓.)
        inputs.push(make_key(0x41, 0));            // A↓ (VK_A = 0x41)
        inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));  // A↑
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0)); // Ctrl↑

        // Step 4: type the path char-by-char. Each char sends PRESS + RELEASE
        // (KEYEVENTF_UNICODE + KEYEVENTF_KEYUP per MSDN SendInput docs).
        // This replaces the selection from Ctrl+A.
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));           // press
            inputs.push(make_unicode_release(ch));   // release
        }

        // (No Enter, no Invoke Save — Rule 47: user wants manual confirmation.)

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        let total = inputs.len() as u32;
        if n != total {
            warn!(
                "v0.5.2 SendInput: queued {total} events, system accepted only {n}; \
                 foreground-lock likely blocked some events (Mavis D3)"
            );
            return false;
        }
        info!(
            "v0.5.2 SendInput Ctrl+L + Ctrl+A + path dispatched \
             ({total} events, no Enter, unicode press+release)"
        );
        true
    }
}
```

**改动 B**:加 `make_unicode_release` helper(在 `make_unicode` 旁边)

```rust
/// D2 (Mavis §1.2) implementation: construct a Unicode keyboard INPUT (UTF-16
/// char press).
fn make_unicode(ch: u16) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(0),
            wScan: ch,
            dwFlags: KEYEVENTF_UNICODE,
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}

/// v0.5.2 (I3 fix, Mavis review): KEYEVENTF_UNICODE also needs a release
/// event per MSDN SendInput docs. Without this, the OS may auto-release on
/// its own (and Chromium usually interprets single unicode events fine), but
/// some apps / dead-key compositions are missed. We pair every press with
/// a release for correctness.
fn make_unicode_release(ch: u16) -> INPUT {
    unsafe {
        let mut input: INPUT = std::mem::zeroed();
        input.r#type = INPUT_KEYBOARD;
        input.Anonymous.ki = KEYBDINPUT {
            wVk: VIRTUAL_KEY(0),
            wScan: ch,
            dwFlags: KEYBD_EVENT_FLAGS(KEYEVENTF_UNICODE.0 | KEYEVENTF_KEYUP.0),
            time: 0,
            dwExtraInfo: 0,
        };
        input
    }
}
```
