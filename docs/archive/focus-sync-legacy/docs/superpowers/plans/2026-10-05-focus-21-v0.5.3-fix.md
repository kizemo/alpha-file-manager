## 0. TL;DR(60 秒)

**v0.5.2 用户实测反馈**:
1. ❌ 路径仍会叠加(address bar 显示 `C:\downloads\C:\logs` 而非 `C:\logs`)
2. ❌ **新 bug**:切换到 Sigma FM 后,焦点会自动切换回下载弹窗
3. ❌ 焦点盗窃违反"不应主动切换焦点,使用者手动切换"

**两个 bug 的根因**(Phase 1 evidence):
1. **Ctrl+A 不 select-all** in WinUI 3 wrapped Save As 的 address bar(WinUI 3 拦截)
2. **`SetForegroundWindow(hwnd)` 主动切焦点**(直接违反用户要求)

**v0.5.3 修复方案**(最小化):
1. **删除 `SetForegroundWindow`**(焦点盗窃 — 用户明确要求)
2. **删除 `AllowSetForegroundWindow`**(无用途,SetForegroundWindow 已删)
3. **Ctrl+A → Home + Shift+End**(基础 Edit 操作,WinUI 3 不太可能拦截)
4. **不动其他**(Rule 47 no Enter / no commit_save_button / NSIS hooks / extension)

## 2. Phase 2 pattern analysis

### 2.1 WinUI 3 wrapped dialog 拦截模式

根据 v0.5.1 + v0.5.2 实测:
| 快捷键 | WinUI 3 Save As 行为 | 期望 |
|---|---|---|
| Ctrl+L | 只 focus,不 select-all | focus + select-all |
| Ctrl+A | 不响应(no select-all)| select-all |

**规律**:WinUI 3 wrapped 拦截 Chrome 的标准快捷键,可能因为是 custom widget 而非标准 Edit。

### 2.2 Home/Shift+End 期望行为

`Home` = 光标到行首(基础 Edit 操作)
`Shift+End` = 选中到行尾(基础 Edit 操作)
**WinUI 3 拦截基础 Edit 操作的概率极低**(它们是 textbox 通用行为,不是 Chrome 扩展)。

如果 address bar 是真 Edit,这两个操作 100% 会 select-all。
如果 address bar 不是 Edit(自定义 widget),这两个操作**可能无效**,但**不会污染**其他东西。

---

## 3. Phase 3 hypothesis

**唯一假设**:**Home + Shift+End 比 Ctrl+A 更可能 select-all**(基础 Edit 操作,WinUI 3 不太可能拦截)。

**预测**:
- 实测 v0.5.3 后,address bar 应该被 select-all → typing 替换
- 如果仍拼接:address bar 不是 Edit(WinUI 3 完全吃 keyboard events),需采用 H2 fallback 路径

### 4.2 改动前(当前 v0.5.2)

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        // D1 [HIGH]: ASFW_ANY = 0xFFFFFFFF. Using 0x00000001 silently fails.
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        // SetForegroundWindow may fail under the Vista+ foreground lock
        // when the sidecar has never been foreground. We log and continue:
        // SendInput targets the foreground thread, not this one.
        let _ = SetForegroundWindow(hwnd);  // ← ⚠️ 焦点盗窃

        let mut inputs: Vec<INPUT> =
            Vec::with_capacity(5 + target_path.encode_utf16().count() * 2);

        // Step 3: Ctrl+L — focus Chromium's address bar.
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
        // Ctrl is still held from the Ctrl↓ above.

        // v0.5.2 Ctrl+A — force select-all before typing.
        inputs.push(make_key(0x41, 0));            // A↓ (VK_A = 0x41)
        inputs.push(make_key(0x41, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

        // Step 4: type the path char-by-char (press + release).
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
            inputs.push(make_unicode_release(ch));
        }

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        // ... log success ...
    }
}
```

### 4.3 改动后(v0.5.3)

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        // v0.5.3 (2026-10-05 user feedback): REMOVED AllowSetForegroundWindow
        // and SetForegroundWindow. The user explicitly requires:
        //   "不应主动切换焦点,而应该使用者手动切换"
        // The SendInput events will reach whatever window currently has
        // focus. If the user has Sigma FM focused (not the dialog), our
        // events would go there. The user's workflow expects them to
        // manually click back to the Save As dialog before Sigma FM
        // path sync can take effect — that is the user's choice.

        let mut inputs: Vec<INPUT> =
            Vec::with_capacity(8 + target_path.encode_utf16().count() * 2);

        // Step 3: Ctrl+L — focus Chromium's address bar.
        // (WinUI 3 Save As may not select-all on Ctrl+L alone, but Ctrl+L
        // still focuses the address bar text input area, which is the
        // precondition for Home/Shift+End to operate on the address bar
        // rather than on whatever else is focused.)
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

        // v0.5.3 (C1 bug fix): Ctrl+A doesn't select-all in WinUI 3 wrapped
        // Save As (WinUI 3 intercepts Chrome's standard Ctrl+A shortcut).
        // Replace with Home + Shift+End — basic Edit operations that WinUI 3
        // is very unlikely to intercept.
        //   Home     → cursor to start of line
        //   Shift+End → select to end of line
        inputs.push(make_key(VK_HOME.0, 0));
        inputs.push(make_key(VK_HOME.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_SHIFT.0, 0));
        inputs.push(make_key(VK_END.0, 0));
        inputs.push(make_key(VK_END.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_SHIFT.0, KEYEVENTF_KEYUP.0));

        // Step 4: type the path char-by-char (press + release per MSDN).
        // The selection from Home+Shift+End gets replaced.
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
            inputs.push(make_unicode_release(ch));
        }

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        let total = inputs.len() as u32;
        if n != total {
            warn!(
                "v0.5.3 SendInput: queued {total} events, system accepted only {n}; \
                 foreground-lock likely blocked some events (Mavis D3)"
            );
            return false;
        }
        info!(
            "v0.5.3 SendInput Ctrl+L + Home+Shift+End + path dispatched \
             ({total} events, no Enter, no focus theft)"
        );
        true
    }
}
```

**改动**:
- 删除:`AllowSetForegroundWindow(ASFW_ANY)` 调用
- 删除:`SetForegroundWindow(hwnd)` 调用
- 删除:Ctrl+A 序列(A↓ + A↑ + Ctrl↑)3 events
- 新增:Home↓↑ + Shift↓ + End↓↑ + Shift↑ = 6 events
- net:**+3 events**(5 → 8 fixed control events),path events 不变

## 8. Memory 沉淀

**规则 50**(v0.5.3):
- **SendInput 在 WinUI 3 wrapped dialog 中不可靠** — Ctrl+L + Ctrl+A 都不工作
- **优先用基础 Edit 操作**(Home/Shift+End)而非浏览器扩展快捷键(Ctrl+L/Ctrl+A)
- **永远不要 SetForegroundWindow** — 用户会拒绝焦点盗窃
- **永远不要 AllowSetForegroundWindow** — 同上
- **如果 SendInput 失败,接受用户的"手动操作"预期**
