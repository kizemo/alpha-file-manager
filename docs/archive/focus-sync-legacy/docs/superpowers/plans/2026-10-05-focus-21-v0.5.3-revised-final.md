## 1. 修正后的诊断(Phase 1-2)

### 1.1 v0.5.2 用户实测反馈
- ❌ 路径仍叠加(`C:\downloads\C:\logs`)
- ❌ 焦点会自动切换回下载弹窗(违反用户"不应主动切换"原则)

### 1.2 根因(精确)
1. **Ctrl+A 在 WinUI 3 wrapped Save As 不 select-all**(WinUI 3 拦截 Chrome 标准快捷键,同 Ctrl+L)
2. **焦点切换**是用户感知的副作用,**真正根因**是 SendInput 投递路径依赖前台窗口(不是 sidecar 主动"偷")

### 1.3 A1 严重回归(避免犯)
**删 SetForegroundWindow 后**:
- 用户在 Sigma FM 导航时,SendInput events 去 Sigma FM 输入框
- dialog 完全收不到 → address bar 不更新
- 比"拼接"更糟:用户视觉上完全无反应

**结论**:**必须保留 SetForegroundWindow**(但用 GetForegroundWindow check + warn 让用户知道焦点状态)。

## 2. Phase 4 实施方案(B1:保留 SetForegroundWindow + 加 verify)

### 2.1 改动范围(1 函数)

**文件**:`sigma-listary-spike/src/uia_inject.rs`
**函数**:`try_send_path_via_sendinput`
**改动**:6 events 替换(Ctrl+A → Home+Shift+End)+ 3 行 verify(log)+ 1 行 log message

### 2.2 改动后代码

```rust
fn try_send_path_via_sendinput(dialog_hwnd: u32, target_path: &str) -> bool {
    let hwnd = HWND(dialog_hwnd as *mut core::ffi::c_void);
    unsafe {
        // Mavis A1 (2026-10-05 第 15 轮): KEEP both AllowSetForegroundWindow
        // and SetForegroundWindow. SendInput dispatches events to the
        // foreground window — if dialog is backgrounded, events go to
        // Sigma FM (worse: would pollute Sigma FM's search box).
        let _ = AllowSetForegroundWindow(ASFW_ANY);
        let _ = SetForegroundWindow(hwnd);

        // Mavis A4: check if dialog actually became foreground. If not,
        // warn user that SendInput may go elsewhere. We don't abort — the
        // user's workflow may legitimately switch focus back to dialog
        // between PUSH and SendInput (race window).
        let current_fg = GetForegroundWindow();
        if current_fg != hwnd {
            warn!(
                "v0.5.3 SendInput: dialog hwnd={hwnd:?} is not foreground \
                 (current={current_fg:?}); events may not reach dialog. \
                 User should manually focus dialog before Sigma FM navigation."
            );
        }

        let mut inputs: Vec<INPUT> =
            Vec::with_capacity(8 + target_path.encode_utf16().count() * 2);

        // Step 3: Ctrl+L — focus Chromium's address bar.
        // (WinUI 3 Save As may intercept Ctrl+L like it does Ctrl+A, but we
        // still send it in case some dialogs support it.)
        inputs.push(make_key(VK_CONTROL.0, 0));
        inputs.push(make_key(VK_L.0, 0));
        inputs.push(make_key(VK_L.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_CONTROL.0, KEYEVENTF_KEYUP.0));

        // Step 3b: Home + Shift+End — basic Edit operations that WinUI 3 is
        // unlikely to intercept (vs. Ctrl+A which is a Chrome extension that
        // WinUI 3 may eat). Replaces v0.5.2's broken Ctrl+A.
        //   Home      → cursor to start of line
        //   Shift+End → select to end of line
        inputs.push(make_key(VK_HOME.0, 0));
        inputs.push(make_key(VK_HOME.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_SHIFT.0, 0));
        inputs.push(make_key(VK_END.0, 0));
        inputs.push(make_key(VK_END.0, KEYEVENTF_KEYUP.0));
        inputs.push(make_key(VK_SHIFT.0, KEYEVENTF_KEYUP.0));

        // Step 4: type the path char-by-char (press + release per MSDN).
        // The selection from Home+Shift+End gets replaced.
        for ch in target_path.encode_utf16() {
            inputs.push(make_unicode(ch));
            inputs.push(make_unicode_release(ch));
        }

        let n = SendInputFn(&inputs, std::mem::size_of::<INPUT>() as i32);
        let total = inputs.len() as u32;
        if n != total {
            warn!(
                "v0.5.3 SendInput: queued {total} events, system accepted only {n}; \
                 foreground-lock likely blocked some events (Mavis D3)"
            );
            return false;
        }
        info!(
            "v0.5.3 SendInput Ctrl+L + Home+Shift+End + path dispatched \
             ({total} events, no Enter)"
        );
        true
    }
}
```

### 2.3 imports 检查

`VK_HOME`, `VK_END`, `VK_SHIFT`, `GetForegroundWindow` 需要在 imports 中:

```rust
use windows::Win32::UI::Input::KeyboardAndMouse::{
    SendInput as SendInputFn, INPUT, INPUT_KEYBOARD, KEYBDINPUT, KEYBD_EVENT_FLAGS,
    VIRTUAL_KEY, VK_L, VK_CONTROL,
    KEYEVENTF_UNICODE, KEYEVENTF_KEYUP,
    VK_HOME, VK_END, VK_SHIFT,  // ← 新增
};
use windows::Win32::UI::WindowsAndMessaging::{
    AllowSetForegroundWindow, SetForegroundWindow, GetForegroundWindow,  // ← 新增
    SendMessageW, WM_KEYDOWN, WM_KEYUP,
};
```

如果 windows-rs 0.62 不 export 某个常量,fallback 用数字虚拟键码:
- `VK_HOME = 0x24`
- `VK_END = 0x23`
- `VK_SHIFT = 0x10`
