# focus-sync v0.5.3 Rollback 复盘 + 最小化修复计划

**日期**: 2026-10-05
**作者**: Claude (MiniMax-M3)
**类型**: Rollback 复盘 + 修复计划(待用户决策)
**状态**: Production 已 rollback 至 v0.5.2 binary(能 sync 但 race condition)

---

## 0. TL;DR(60 秒)

**v0.5.3 失败根因**:
- 保留 `SetForegroundWindow(dialog)` 但 dialog 不在前台时 SetForegroundWindow 在 Vista+ foreground lock 下失败
- SendInput events 投递到 Sigma FM(foreground window),**完全不到 dialog**
- 用户看到 "完全没反应"——address bar 没动,文件名没变,看似 hang

**v0.5.2 实际 work 是 race condition**:
- v0.5.2 测试时 dialog 偶然在前台(用户在 Sigma FM 切路径前先点过 dialog)
- SetForegroundWindow no-op(SendInput 投递到 dialog)
- v0.5.3 测试时用户**没**回 dialog,Sigma FM 在前台 → events 去错地方

**真正最小化修复**(1 行改动):
- v0.5.3 已经把 SetForegroundWindow 后的 `GetForegroundWindow` check 改为 **abort** 而不是 warn
- abort 触发 H2 fallback(SetValue + restore filename,50ms flicker)
- 不静默 success 误导用户

**已 rollback**:Production 用 v0.5.2 binary。v0.5.3 source code 已实施,但**未部署**(留在工作树作 record)。

```

[14:20:01] [INFO] v0.5.3 SendInput Ctrl+L + Home+Shift+End + path dispatched (26 events, no Enter)
[14:20:01] [INFO] v0.5.1 H1 succeeded: SendInput Ctrl+L set address bar
[14:20:01] [INFO] Injection succeeded via UI Automation.
```

### 1.2 关键事实解码

| 字段 | 值 | 含义 |
|---|---|---|
| `dialog hwnd=HWND(0x931118)` | dialog HWND | Save As dialog 窗口 |
| `current=HWND(0x59410ea)` | foreground HWND | Sigma FM 窗口(不是 dialog!) |
| **is not foreground** | dialog 不在前台 | events 投递到 0x59410ea(错)|
| dispatched 26 events | OS 接收 26 events | 但 events 去了 foreground 窗口,不是 dialog |
| **H1 succeeded** | 误报 | OS 接受 dispatch,但实际效果 0 |
| **Injection succeeded** | 误报 | 同上 |

### 1.3 事件投递路径错误

```
v0.5.3 SendInput 序列:
  Ctrl↓ → L↓ → L↑ → Ctrl↑ → Home↓ → Home↑ → Shift↓ → End↓ → End↑ → Shift↑ → (path↓ + path↑) × 7

target: Save As dialog (hwnd 0x931118)
但 dialog 不在前台,foreground 是 Sigma FM (hwnd 0x59410ea)

实际投递:
  Ctrl↓ → Sigma FM 内部 Ctrl+L handler(可能绑定 "go to address bar")
  L↓ → Sigma FM address bar focus(可能 work,可能 not)
  L↑ → release
  Ctrl↑ → release
  Home↓ → Sigma FM address bar cursor 到开头
  Home↑
  Shift↓ → modifier down
  End↓ → Sigma FM address bar cursor 到结尾 + select
  End↑
  Shift↑
  (path↓ + path↑) × 7 → Sigma FM address bar 被填"C:\local"

Save As dialog 完全没动。
filename 没变(对话框没收到任何 event)。
```

### 1.4 误报:H1 / Injection succeeded

```rust
// inject_via_uia line ~548:
if try_send_path_via_sendinput(dialog_hwnd, target_path) {
    info!("v0.5.1 H1 succeeded: SendInput Ctrl+L set address bar (user navigates + saves manually)");
    return Ok(DialogOutcome::AddressBarWritten);
}
```

`try_send_path_via_sendinput` 返回 `true` 因为:
- `SendInputFn` 返回 26(全部 events 被 OS 接收)
- 我们的代码认为"OS 接收了 events = 成功"
- **但 OS 把 events dispatch 到了 Sigma FM(不是 dialog)**,所以实际无效

**应该改**:`SendInputFn` 之后,`GetForegroundWindow` 检查 dialog 是否真的在前台,如果不在则 **return false** 触发 H2 fallback。

### 1.5 v0.5.2 为什么 "work"

**v0.5.2 测试时**:
- 用户预先点回 Save As dialog(dialog 是 foreground)
- sidecar SetForegroundWindow no-op(success,因为已经在 foreground)
- SendInput 到 dialog → work
- 用户看到 "Sync OK"

**v0.5.3 测试时**:
- 用户在 Sigma FM 切路径,**dialog 在 background**
- SetForegroundWindow 失败(Vista+ foreground lock,sidecar 不是 foreground process)
- SendInput 到 Sigma FM → 完全无效
- 用户看到 "Sync 完全没反应"

**v0.5.2 实际 work = race condition**,不是真 fix。

## 2. Phase 2 pattern — 修复模式对比

### 2.1 4 条修复方向

| 模式 | 行为 | 副作用 | 推荐 |
|---|---|---|---|
| **A**: 删 SetForegroundWindow + GetForegroundWindow check + abort | dialog 不在前台 → return false → H2 fallback | 50ms flicker | ⭐ 推荐 |
| **B**: extension PUSH 前 SetForegroundWindow(dialog) | extension 抢 dialog 焦点 | extension 偷焦点(违反用户需求)| 不推荐 |
| **C**: extension PUSH 前 AllowSetForegroundWindow(sidecar_pid) | sidecar 获 grant,SetForegroundWindow 不再被锁 | extension 仍可能偷焦点 | 不推荐 |
| **D**: 完全弃用 SendInput,只用 H2 fallback(无 50ms flicker 仍能 sync) | 直接 SetValue 1001 Edit → chromium 更新 breadcrumb → restore | filename 短暂污染 | 备选 |

### 2.2 推荐路径:**A**(最小化改动)

1 行关键改动 + 1 行 warn 替换:
```rust
// 当前 v0.5.3:
let current_fg = GetForegroundWindow();
if current_fg != hwnd {
    warn!("...");
}
// → continue SendInput (silently fail)

// 改为:
let current_fg = GetForegroundWindow();
if current_fg != hwnd {
    warn!("...");
    return false;  // ← 触发 H2 fallback
}
// → SendInput only when dialog IS foreground
```

**最小化**:1 行 `return false;` 加在 warn block 内,2 行 log message 微调。

### 3.3 改动后(v0.5.4 关键修复)

```rust
unsafe {
    let _ = AllowSetForegroundWindow(ASFW_ANY);
    let _ = SetForegroundWindow(hwnd);

    // v0.5.4 (2026-10-05 复盘): 必须 abort 而不是 warn。
    // 之前(warn + continue)导致 SendInput events 去 Sigma FM 搜索框
    // (因为 dialog 不在前台)— 用户看到"完全没反应"且误报 H1 succeeded。
    // 改为 abort:return false → 触发 H2 fallback(SetValue + restore filename,
    // 50ms flicker)。H2 在 WinUI 3 wrapped dialog 上已知 work(plan v0.5.1)。
    let current_fg = GetForegroundWindow();
    if current_fg != hwnd {
        warn!(
            "v0.5.4 SendInput: dialog hwnd={hwnd:?} is not foreground \
             (current={current_fg:?}); aborting to trigger H2 fallback."
        );
        return false;
    }

    let mut inputs: Vec<INPUT> = ...;
    // ... build & send SendInput ...
}
```

### 3.4 fallback chain(完整)

```
Edge Save As dialog (WinUI 3 wrapped):
  COM IFileDialog::SetFolder              ← Layer 1 (round 19f)
    ↓ fail (AccessibleObjectFromWindow failed)
  UIA 4-layer fallback:
    detect WinUI 3 wrapped (has_filename_host + has_1001)
      ↓
      H1 SendInput Ctrl+L + Home+Shift+End + path:
        GetForegroundWindow check:
          dialog  foreground → SendInput → return AddressBarWritten
          dialog !foreground → abort → return false → H2
      ↓ return false
      H2 SetValue target + SetValue original (50ms sleep):
        SetValue 1001 = "C:\evid" → chromium 更新 breadcrumb
        Sleep(50ms)
        SetValue 1001 = original filename → 恢复
        return AddressBarWritten
      ↓ return false
      F3 v0.5.0 baseline: SetValue + Invoke Save(known pollution)
      ↓ return false
      Unsupported + notification
```

## 6. Memory 沉淀(规则 51)

**规则 51**(v0.5.4):
- **SendInput 后必须 GetForegroundWindow verify dialog 在前台**——不在前台就 **return false**(不 warn + continue)
- **SendInput 接受 events ≠ SendInput 投递成功**——OS 接受 events 但 dispatch 到 foreground window,可能不是 dialog
- **"H1 succeeded" + "Injection succeeded" 日志会误导**——必须在前台 check 后才能报告 success
- **race condition 不是 fix**——v0.5.2 测试时 dialog 在前台偶然 work,不是真 fix
