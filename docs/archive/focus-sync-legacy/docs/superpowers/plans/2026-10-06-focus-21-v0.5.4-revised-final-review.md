### 2.3 规则 51/52 评估

**规则 51**(v0.5.4):
- ✅ **SendInput 后必须 GetForegroundWindow verify dialog 在前台** — 不在前台就 **return false**(不 warn + continue)
- ✅ **SendInput 接受 events ≠ SendInput 投递成功**
- ✅ **"H1 succeeded" + "Injection succeeded" log 是误报**
- ✅ **race condition 不是 fix**
- ✅ **user 实测前必须确认 dialog 在前台**(testing workflow assumption)— 这是**新增**的关键 rule,我之前 review 漏掉

**规则 52**(v0.5.4):
- ✅ **SendInput 在 sidecar 单独进程下不可靠** — Vista+ foreground lock + race condition
- ✅ **SendInput 是 "best effort" 机制** — fallback 必须 ready
- ✅ **production-critical path 不应依赖 SendInput** — 主要靠 UIA SetValue
- ✅ **SendInput work 当且仅当**:
  - calling process 是 foreground
  - OR extension 已 grant foreground permission
  - AND dialog 在 target foreground 状态

✅ **规则 51/52 是 13 轮 review 沉淀以来最重要的认知**。

### 2.4 关于规则 52 的细节

规则 52 第 4 条 "SendInput work 当且仅当":
- calling process 是 foreground → sidecar 不是(Sigma FM 是)
- OR extension 已 grant foreground permission → extension 没调(plan §5.2 verified)
- AND dialog 在 target foreground 状态 → user 实测时 dialog 在 background

**3 个 AND conditions 全不满足** → SendInput 必然 fail → race condition

**这是 v0.5.4 修复的逻辑基础**:`GetForegroundWindow` check 立即发现 dialog 不在 foreground → abort → H2 fallback。

### 3.6 🟡 B2 — plan §3.1 H2 代码不准确

**plan 显示的 H2 代码**用 `?` 操作符(直接 propagate error)。

**actual source H2 代码**(verified by read, line 340-376):
```rust
fn try_h2_restore_filename(edit: &IUIAutomationElement, target_path: &str) -> bool {
    let value: IUIAutomationValuePattern = unsafe {
        match edit.GetCurrentPatternAs(UIA_ValuePatternId) {
            Ok(v) => v,
            Err(e) => {
                warn!("v0.5.1 H2: failed to acquire ValuePattern: {e:?}");
                return false;
            }
        }
    };
    let original_filename = unsafe { value.CurrentValue() }
        .unwrap_or_default()
        .to_string();
    if original_filename.is_empty() {
        warn!("v0.5.1 H2: original filename is empty; skipping restore path");
        return false;
    }
    if let Err(e) = unsafe { value.SetValue(&BSTR::from(target_path)) } {
        warn!("v0.5.1 H2: SetValue target_path failed: {e:?}");
        return false;
    }
    std::thread::sleep(std::time::Duration::from_millis(50));
    if let Err(e) = unsafe { value.SetValue(&BSTR::from(original_filename.as_str())) } {
        warn!("v0.5.1 H2: SetValue restore filename failed: {e:?}");
        return false;
    }
    info!(
        "v0.5.1 H2: target_path written and original filename restored ({} bytes)",
        original_filename.len()
    );
    true
}
```

**actual H2 比 plan 显示的复杂**:
- 用 `match` 处理 `Result`,**不是** `?`(因为函数返回 `bool` 不是 `Result`)
- 用 `if let Err` 处理 SetValue 失败
- 用 `unwrap_or_default()` 处理 CurrentValue 失败
- 检查 original_filename.is_empty() 跳过 restore
- 每个失败点都有 warn log

**影响**:plan §3.1 是简化版本,**实际 H2 已实施完整**(plan v0.5.1 阶段)。**实际代码已 work**。

**修复建议**:plan §3.1 应说明"H2 在 source 已实施(plan v0.5.1 阶段),plan §3.1 显示简化版本,完整代码见 source `uia_inject.rs::try_h2_restore_filename`"。

**非阻塞**。
