## 0. TL;DR(60 秒)

**v0.5.3 失败根因**(Mavis 第 19 轮确认):
- SendInput 后 GetForegroundWindow check **warn 但不 abort**
- Dialog 不在前台时 events 投递到 Sigma FM,**完全不到 dialog**
- v0.5.2 work 是 **race condition**(dialog 偶然在前台)
- "H1 succeeded" / "Injection succeeded" 是**误报**

**v0.5.4 修复**:**1 行改动** — `GetForegroundWindow check` block 内加 `return false;` 触发 H2 fallback(UIA SetValue,不需 foreground)。

**采纳 Mavis 3 处优化**:

| # | Mavis 优化 | 采纳方式 |
|---|---|---|
| **O1** | H2 fallback 是否 work when dialog 不在前台 | ✅ §3.4 U-V 必测 Scenario B;flag H2 fail 应急 |
| **O2** | race condition SetForegroundWindow + GetForegroundWindow | ✅ 接受(H2 fallback 兜底)|
| **O3** | "Mavis I2 假设错了" 含糊 | ✅ §5.2 写明:v0.5.4 保留 I2 fix,不恢复 extension AllowSetForegroundWindow |

**改动范围**:**1 行 return false + 4 文件版本号 bump + memory 沉淀**。

| `dialog hwnd=0x931118` | dialog 窗口 | Save As dialog |
| `current=0x59410ea` | foreground 窗口 | **Sigma FM**(不是 dialog)|

### 1.3 实际事件投递路径(错位)

```
v0.5.3 SendInput 26 events:
  Ctrl+L  → Sigma FM 内部 Ctrl+L handler
  Home    → Sigma FM address bar cursor 到开头
  Shift+End → Sigma FM address bar select
  (path) → Sigma FM address bar 被填 "C:\local"
```

### 1.4 v0.5.2 race condition(为什么 work)

- v0.5.2 测试时用户预先点回 Save As dialog(dialog 是 foreground)

- 用户看到 sync OK,**偶然 race condition 成功**

v0.5.3 测试时用户**没**点回 dialog,Sigma FM 在前台 → events 错位 → "完全没反应"。

## 2. v0.5.4 修复方案(采纳 Mavis A1/A4/I1 + 新增 abort)

### 2.1 改动范围(**严格最小化,1 行**)

**文件**:`sigma-listary-spike/src/uia_inject.rs`
**函数**:`try_send_path_via_sendinput`
**改动**:`if current_fg != hwnd` block 内加 `return false;` + log message 更新

### 2.2 改动前(v0.5.3,warn + continue)

```rust
unsafe {
    let _ = AllowSetForegroundWindow(ASFW_ANY);
    let _ = SetForegroundWindow(hwnd);

    let current_fg = GetForegroundWindow();
    if current_fg != hwnd {
        warn!(
            "v0.5.3 SendInput: dialog hwnd={hwnd:?} is not foreground \
             (current={current_fg:?}); events may not reach dialog."
        );
        // ⚠️ 仍 continue SendInput (race condition silent fail)
    }

    let mut inputs: Vec<INPUT> = ...;
    // ... build & send SendInput ...
}
```

### 2.3 改动后(v0.5.4,**warn + abort**)

```rust
unsafe {
    let _ = AllowSetForegroundWindow(ASFW_ANY);
    let _ = SetForegroundWindow(hwnd);

    // v0.5.4 (2026-10-06 复盘): MUST abort instead of warn+continue.
    // Per Mavis review: SendInput events dispatch to foreground window
    // (possibly Sigma FM), not dialog — silent fail with misleading
    // "H1 succeeded" log. Abort to trigger H2 fallback (UIA SetValue,
    // no foreground dependency, known to work from v0.5.1).
    let current_fg = GetForegroundWindow();
    if current_fg != hwnd {
        warn!(
            "v0.5.4 SendInput: dialog hwnd={hwnd:?} is not foreground \
             (current={current_fg:?}); aborting to trigger H2 fallback."
        );
        return false;
    }

    let mut inputs: Vec<INPUT> = ...;
    // ... build & send SendInput ...
}
```

**关键改动**:1 行 `return false;`(替换 warn block 末尾的 silent continue)。

## 3. Fallback chain(完整)

```
Edge Save As dialog (WinUI 3 wrapped):
  Layer 1: COM IFileDialog::SetFolder              ← round 19f
    ↓ fail (AccessibleObjectFromWindow failed)
  Layer 2: H1 SendInput Ctrl+L + Home+Shift+End:
    GetForegroundWindow check:
        dialog foreground → SendInput → return AddressBarWritten ✓
        dialog !foreground → return false → Layer 3
    ↓ return false
  Layer 3: H2 SetValue target + restore original (50ms sleep):
    UIA SetValue → chromium 更新 breadcrumb → SetValue original
    return AddressBarWritten ✓ (UIA 不需 foreground)
    ↓ return false
  Layer 4: F3 v0.5.0 baseline SetValue 1001:
    (redundant with Layer 3, but kept as safety net)
    ↓ return false
  Layer 5: Unsupported + notification
```

### 3.1 H2 实际如何(UIA SetValue)

```rust
fn try_h2_restore_filename(edit: &IUIAutomationElement, target_path: &str) -> bool {
    let value = unsafe { edit.GetCurrentPatternAs::<IUIAutomationValuePattern>(UIA_ValuePatternId) }?;
    // Read current (user's original filename)
    let original = unsafe { value.CurrentValue() }?.to_string();
    // SetValue target_path
    unsafe { value.SetValue(&BSTR::from(target_path)) }?;
    // 50ms sleep: chromium needs time to update breadcrumb
    std::thread::sleep(std::time::Duration::from_millis(50));
    // Restore original filename
    unsafe { value.SetValue(&BSTR::from(&original)) }?;
    true
}
```

**UIA SetValue 不依赖 foreground**(plan §2.5 已实施)。

### 3.2 实际有效 layers

- Layer 1: Win32 IFileDialog work(影刀 RPA / Photos / Edge Legacy)
- Layer 2-3: WinUI 3 wrapped Save As(dialog 在/不在前台)
- Layer 4: redundant with Layer 3(safety net)
- Layer 5: 完全 fail notification

**真实依赖 foreground 的只有 Layer 2**。Layer 3+ 都用 UIA SetValue,不需要 foreground。

## 4. Mavis O1 — H2 实测 verify(采纳)

### 4.1 plan §3.5 假设

H2 fallback 在 dialog 不在前台时 work,但**未实测 verify**。

### 4.2 实际情况

UIA SetValue 通过 COM 调用,理论上不需要 foreground。但 WinUI 3 wrapped dialog 在某些情况下可能要求 foreground:
- dialog 在 UAC / elevated process
- dialog 已被 UIA 释放(element handle stale)
- dialog 在另一个 session

### 4.3 实测建议(采纳 Mavis O1)

实施 v0.5.4 后,**必测**:
- **Scenario A**:dialog 在前台 → H1 → return AddressBarWritten ✓
- **Scenario B**(关键):dialog 在 background(Sigma FM 在前)→ H1 abort → H2 → 期望 return AddressBarWritten ✓
- **Scenario C**:H2 fail → F3 → 如果 F3 也 fail → Unsupported

### 4.4 如果 H2 fail

- F3 (v0.5.0 baseline)也 fail → Unsupported + notification(plan §4 worst case)
- user 接受 50ms flicker 才用 v0.5.4,不接受就退回 v0.5.2 race condition

## 5. Mavis O3 — "Mavis I2 假设错了" 明确化

### 5.1 事实重建(plan §3.5 of v0.5.3-c1-fix-review)

v0.5.3-c1-fix 计划推荐删除 extension 中的:
```javascript
const sidecarPid = await getSidecarPid();
if (sidecarPid !== null) {
    await allowSetForegroundWindow(sidecarPid);
}
```

### 5.2 实际:extension 没有这段代码

v0.5.3 ship 时,`release/extension/dist/index.js` 中 **没有** `getSidecarPid` 或 `allowSetForegroundWindow` 调用(plan §3.5 of v0.5.3-final-implementation-review.md 验证)。

也就是说:
- v0.5.2: extension 没调 AllowSetForegroundWindow(sidecar_pid)。**race condition 是 dialog 偶然在前台**。
- v0.5.3: extension 仍没调。但用户在 Sigma FM 切路径,dialog 不在前台 → race condition fail → 完全没反应。

### 5.3 v0.5.4 怎么处理 I2?

**保留 v0.5.3 状态**(不调 extension):
- v0.5.3 没部署 I2 fix(extension 没改)
- v0.5.4 不需要改 extension
- v0.5.4 改 sidecar 的 `GetForegroundWindow` check + abort

**新思路**(Mavis 第 19 轮 O3 修正):
- 删 extension grant = 防止焦点盗窃(实际已删)
- SendInput race = v0.5.2 test workflow 的偶然
- v0.5.4 = `SendInput if dialog foreground, else H2 fallback`
- H2 fallback 是 **新的 sync 机制**,不依赖 race condition

| 禁止 | 原因 |
|---|---|

| ❌ 重新加 Enter 到 SendInput | Rule 47 |

## 8. Memory 沉淀(规则 51 + 52)

### 规则 51(v0.5.4)—— 复盘核心洞察

- **SendInput 后必须 GetForegroundWindow verify dialog 在前台**——不在前台就 **return false**(不 warn + continue)
- **SendInput 接受 events ≠ SendInput 投递成功**——OS 接受 events 但 dispatch 到 foreground window
- **"H1 succeeded" + "Injection succeeded" log 是误报**——基于 SendInputFn 返回值(OS accept),不验证 dispatch 目标
- **race condition 不是 fix**——v0.5.2 测试时 dialog 偶然在前台,不是真 fix
- **user 实测前必须确认 dialog 在前台**(testing workflow assumption)

### 规则 52(v0.5.4)—— SendInput 在 sidecar 不可靠

- **SendInput 在 sidecar 单独进程下不可靠**——Vista+ foreground lock + race condition
- **SendInput 是 "best effort" 机制**——fallback 必须 ready
- **production-critical path 不应依赖 SendInput**——只作为 best-effort,主要靠 UIA SetValue
- **SendInput work 当且仅当**:
  - calling process 是 foreground
  - OR extension 已 grant foreground permission
  - AND dialog 在 target foreground 状态
