## 2. 6 个 Blocker 详细分析

### Blocker B-1:Fix B 早期 return 分支没调 `mark_first_push_received`(CRITICAL)

**Plan §5.2 文件 C**:
```rust
state.set_current_path(path.clone());    // line 188 (current source)
state.mark_first_push_received();       // ← v0.5.5 (plan proposed)
log_event(&Event::SpikeError {
    kind: "path_update".into(),
    ...
});
```

**Bug**:`mark_first_push_received()` 调用**在 `path_unchanged` early-return 之后**:

`http_server.rs:175-185` 当前代码:
```rust
let prev_path = state.get_current_path();
let path_unchanged = prev_path == path;
if path_unchanged {
    log_event(...);
    let resp = ResponseBody::Ok { ok: true, error: None };
    return respond_json(request, 200, &resp);    // ← EARLY RETURN
}

state.set_current_path(path.clone());    // ← 只在 path_unchanged == false 时执行
log_event(...);
```

**场景**:
1. sidecar 启动, `state.current_path = "C:\\"` (sentinel), `first_push_received = false`
2. extension first PUSH: `{"path": "C:\\"}` (== sentinel, 比如 user 在 C:\\ 根目录)
3. `prev_path = "C:\\"` == `path = "C:\\"` → `path_unchanged = true` → **early return**
4. `mark_first_push_received` 永远不 fire
5. user 开 dialog with initial_path=xxx ≠ "C:\\"
6. `opened_write_back` 检查: `state.has_first_push_received() == false` → **SKIP**
7. user 看不到 sync,**虽然 extension 实际有 PUSH,只是 PUSH 等于 sentinel**

**Fix B-1 推荐方案**:把 `mark_first_push_received()` 调用放进 `set_current_path()` 本身,**或者** 在 early-return 分支也调一次。

**推荐**(更 clean):
```rust
// state.rs:89-98 改写
pub fn set_current_path(&self, p: String) {
    let mut guard = self.current_path.lock().unwrap_or_else(|e| e.into_inner());
    *guard = p;
    let ts = SystemTime::now()...;
    self.last_ping_received_ts.store(ts, Ordering::Relaxed);
}

// 新方法:标记 first push
pub fn mark_first_push_received(&self) {
    self.first_push_received.store(true, Ordering::SeqCst);
}
```

```rust
// http_server.rs 把 mark 调用放到 SET 里
state.set_current_path(path.clone());
state.mark_first_push_received();
log_event(...);

// http_server.rs early-return 分支也调
if path_unchanged {
    state.mark_first_push_received();    // ← v0.5.5 在 early-return 也调
    log_event(...);
    return respond_json(request, 200, &resp);
}
```

或者更简洁:`set_current_path` 内部总是 set `first_push_received = true`,然后 `mark_first_push_received` 是个空方法保留向后兼容。但 semantic 不一样。

**最简洁方案**:**修改 `set_current_path` 总是 mark**:
```rust
pub fn set_current_path(&self, p: String) {
    let mut guard = self.current_path.lock().unwrap_or_else(|e| e.into_inner());
    *guard = p;
    let ts = SystemTime::now()...;
    self.last_ping_received_ts.store(ts, Ordering::Relaxed);
    // v0.5.5: always mark first push as received when path is set,
    // even if path didn't change (covers early-return dedup branch).
    self.first_push_received.store(true, Ordering::SeqCst);
}
```

然后 `mark_first_push_received()` 方法可以保留(向后兼容),但 http_server 不需要显式调。

### 改进 I-1:Fix D 的 else-if 冗余条件

Plan §5.4:
```rust
} else if !state.has_first_push_received() && !initial_path.is_empty() && initial_path != current {
    log_event(...);

```

**问题**:如果 if 分支 `if !initial_path.is_empty() && initial_path != current && state.has_first_push_received()` 没进,那一定是这三个条件中至少一个不满足。else if 重复前两个条件冗余。

**推荐**:
```rust
if !initial_path.is_empty() && initial_path != current {
    if state.has_first_push_received() {
        // ... existing write-back ...
    } else {
        log_event(&Event::SpikeError {
            kind: "opened_write_back_skip_sentinel".into(),
            message: format!(
                "dialog path='{}' current='{}' (sentinel); skipping until first push received",
                initial_path, current
            ),
            ts: now_iso8601(),
        });
    }
}
```

或者更紧凑:
```rust
if !initial_path.is_empty() && initial_path != current {
    if state.has_first_push_received() {
        // existing write-back
    } else {
        log_event(...);  // sentinel skip diagnostic
    }
}
```
