### N-4 (重要,推荐):U-V 测试 inline 复制 production guard,未测集成

**问题**:v2 §6.2 line 696-708 `opened_write_back_fires_for_legitimate_root_path`:
```rust
let should_write = !initial_path.is_empty()
    && initial_path != current
    && state.has_first_push_received();
assert!(should_write, "...");
```

这个测试是**复制 production guard 的逻辑**(在 main.rs:352-385)。如果 production guard 改了(例如加 `&& !state.is_initialized()`),这个 test **不会 catch**——它只测自己的复制。

**更好的做法**:把 production guard 提取成 helper function,production code + tests 都用:

```rust
// state.rs (新 helper)
impl AppState {
    pub fn should_opened_write_back(&self, initial_path: &str, current: &str) -> bool {
        !initial_path.is_empty()
            && initial_path != current
            && self.has_first_push_received()
    }
}

// main.rs:352-385
if state.should_opened_write_back(&initial_path, &current) {
    // ... write-back ...
} else if /* sentinel skip case */ {
    // ... log ...
}

// test (state.rs §6.2)
#[test]
fn opened_write_back_fires_for_legitimate_root_path() {
    let state = AppState::new("".into(), 1);
    state.set_current_path("C:\\".into());
    assert!(state.should_opened_write_back("file.zip", "C:\\"));
}
```

**好处**:
- production 与 test 用同一函数 → test 自动 cover production logic
- future change 自动被 test 验证
- 单一 source of truth

**当前 v2 plan 没做这个 refactor**。Round 22 review 也没指出(我看测试时假设 production logic 是稳定接口)。

**建议**:v2 plan 加一个 `should_opened_write_back` helper,这样 U-V10/U-V11/U-V14 实际是 test production code,不是 test 复制品。
