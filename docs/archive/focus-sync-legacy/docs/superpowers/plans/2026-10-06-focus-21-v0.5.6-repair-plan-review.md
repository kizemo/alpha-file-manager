## 1. T-1(CRITICAL):fallback 不产生导航

### 1.1 计划的 fallback 链路推演

```
should_opened_write_back 返回 true
   ↓
main.rs:364  write_path(&state, hwnd, &current="C:\\", false)
   ↓
writer.rs:73  inject_folder_path(state, hwnd, "C:\\", should_commit)
   ↓
uia_inject.rs:511  try_set_folder_via_com(hwnd, "C:\\")
   │  → AccessibleObjectFromWindow(OBJID_NATIVEOM)
   │  → 如果失败 → return false
   ↓
uia_inject.rs:518  inject_via_uia(hwnd, "C:\\", should_commit)
   ↓
uia_inject.rs:667  value.SetValue(&BSTR::from("C:\\"))   ← 写到 best_edit
```

### 1.2 关键:`should_commit = false`

`main.rs:364-371` 传入的第四个参数是 `false`(v0.5.1 起所有路径都不 auto-Invoke)。

`uia_inject.rs:662-666` 明确写着:
```rust
// v0.5.1: should_commit is ignored at the injection layer — the user
// wants manual save confirmation for every code path.
```

**所以整条链路里没有任何一处会触发导航。** `SetValue("C:\\", best_edit)` 只是设置文本。

### 1.3 `best_edit` 是 filename Edit,不是地址栏

Fix A 之后,`uia_inject.rs` 打分:
- `1148` → 100(filename combo box)
- `1001` → 90(filename Edit)
- `41477` → **已排除**(Fix A `continue` 过滤)

`reader.rs:48` 独立印证:
```rust
if control_type == UIA_EditControlTypeId && best_edit.is_none() {
    best_edit = Some(element);   // 第一个 Edit,不区分 id
}
```
`read_path` 读出来的是**用户输入的 filename**(spike.log: `path="11.politics"`,`path="AutoGET_V1.1..."`)。

**所以 `SetValue("C:\\", best_edit)` = 把 `C:\` 写进用户正在输入的文件名框。**

### 1.4 这是用户 100+ 轮最初的原始投诉

用户第一条消息的原话:

> **dialog 跳转 but path 字段被污染(breadcrumb updates, but filename field gets overwritten with the path)**
> **dialog 真正跳转 + 不要把路径写进 filename 字段**

**计划的 fallback 做的正是后半句禁止的事。**

### 1.5 计划 §4.4 把这个当成验收标准(最严重)

计划 §4.4 step 2:
> 期望:dialog **address bar 出现 "C:\\"(sentinel),或 filename box 同步出现**

**"filename box 同步出现"被写成 PASS 条件。**

但 `SetValue` 到 filename box:
- ❌ 不改变 dialog 当前目录(breadcrumb 不动)
- ❌ 用户看到文件名变成 `C:\`,保存会失败
- ✅ 只是把路径字符串塞进了文件名框

**这不是"同步",这是"污染"。** 计划把 bug 当成了验收标准。

## 2. T-2(HIGH):`initial_path != current` 语义错位

### 2.1 两个值的语义

| 变量 | 来源 | 语义 | 实例 |
|---|---|---|---|
| `initial_path` | `reader::read_path` | 用户输入的**文件名** | `"11.politics"` / `"AutoGET_V1.1..."` |
| `current` | `state.get_current_path()` | Sigma FM 的**目录路径** | `"C:\\"` / `"D:\\projects"` |

**这是两个不同语义维度的值。**

### 2.2 后果

`initial_path != current` 在几乎所有情况下都是 **true**:
- `"11.politics" != "C:\\"` → true
- `"report.docx" != "D:\\projects"` → true
- 只有当文件名**恰好等于**目录路径字符串时才 false(几乎不可能)

**所以这个条件不是"去重保护",它是恒真的噪声条件。** 它给人"做了去重"的错觉,实际不起任何过滤作用。

### 2.3 更严重:它掩盖了真正的去重需求

真正的去重应该是 `last_known_path`(`state.rs:331-334` 已有):
```rust
state.register_dialog(DialogInfo {
    last_known_path: initial_path.clone(),   // ← 这个才是 dialog 维度
    ...
});
```

`main.rs:403-408` 在写回后更新 `last_known_path = current`,这才是有意义的去重(防止 monitor 重复 emit Opened 时反复写)。

**`initial_path != current` 是残留的无效条件。**

## 3. T-3(MEDIUM):fallback 写的是 sentinel,不是真实路径

计划 §2.2 把 `default_value` 退回 `"C:\\"`。

于是 fallback 路径下:
```
current = "C:\\"   ← sentinel,不是用户真实浏览路径
SetValue(1001_edit, "C:\\")
```

**用户得到的是"文件名框被塞了 C:\"。** 这不是"降级同步",是"降级污染"。

Claude 计划的 §5 结尾自己承认了矛盾:
> v0.5.6 的 fallback 应该比 v0.5.4 更精准(v0.5.4 写 `C:\`,v0.5.6 写 `state.current_path`,**正常情况下是真实路径**)

**但"正常情况下"= extension PUSH 正常 = fallback 根本不触发。** fallback 只在 PUSH 失败时触发,而那时 `current_path` **必然**是 sentinel。

**这是逻辑自相矛盾:fallback 分支的定义就是"current_path 不可信"。**

## 6. 修正建议

### 6.1 修正 1(核心):区分"导航"和"填文本"

**问题**:当前架构里 `SetValue(1001)` 被当作"导航"用,但它只是填文本。

**方案 A(推荐,最小改动)**:认清现实,只保留 COM 导航路径

```rust
// uia_inject.rs:667 附近 —— SetValue 后明确告知"这只是设置文本"
unsafe { value.SetValue(&BSTR::from(target_path))? };
debug!("UIA SetValue on automation_id='{}' (text only, no navigation \
        — Rule 47 forbids auto-commit)", current_automation_id(&edit));
```

然后**在 plan 里改掉验收标准**:fallback 的成功标准不是"导航",而是"文件名字段被写入目标路径"(这本身就是已知污染,但比什么都不做可接受,且用户可见可察觉)。

**方案 B(正确但工作量更大)**:让 native `#32770` dialog 真正导航

```rust
// fallback 优先走 COM SetFolder,不依赖 extension PUSH
if !self.has_first_push_received() {
    // current 是 sentinel,导航到 C:\ 至少是确定的
    if try_set_folder_via_com(hwnd, &current) { return true; }  // 真的导航了
}
// COM 失败才降级到 SetValue
```

`try_set_folder_via_com` 已经在 `uia_inject.rs:511` 被调用了 —— **它本来就尝试导航**,失败才降级到 `SetValue`。

**所以真正的改进是:让 COM 路径更可靠,而不是恢复 SetValue 到 filename。**

### 6.2 修正 2:删掉无效条件

```rust
// state.rs:131 — 删掉恒真的 initial_path != current
pub fn should_opened_write_back(&self, initial_path: &str) -> bool {
    !initial_path.is_empty()
}
```

真正的去重由 `last_known_path` 负责(main.rs:403-408 已实现)。

### 6.3 修正 3:§4.4 验收标准重写

**删掉**:
- step 2 的 "或 filename box 同步出现"
- step 3 的 "address bar 变成 D:\projects"(不可能通过)

**改为**:
```bash
# 1. 启 sidecar → /health 确认 first_push_received=false
# 2. 打开任意 Save As dialog
# 3. spike.log 必须出现:
#    - opened_write_back          (fallback 写入被触发)
#    - Write 或 WriteFailed       (实际写入了,或明确失败)
# 4. 如果出现 WriteFailed reason=unsupported_dialog_type
#    → 说明 Fix A 把这个 dialog 判为不支持,记录为 P2 followup
# 5. 用户观察:dialog 当前目录是否变化
#    → 变化 = COM SetFolder 成功(真正的导航)
#    → 未变 = 降级到 SetValue,已知限制,如实记录
```

### 6.4 修正 4:Shell 语法

全部改成 PowerShell。

## 8. 对"不要再犯这些错误"的直接回应

你问:为什么多轮优化无效?

**我的结构性错误有三个,plans 层无法修正:**

### 错误 1:我把"写入成功"当成了"功能可用"

`Write strategy="uia"` 出现在日志里,我就认为"同步成功了"。

**实际上它只是往 filename 框写了字符串。** 用户看到的"同步到 filename 处"就是这个污染现象,**从来都不是成功**。

**我从来没验证过 "dialog 的当前目录是否真的变了"。**

### 错误 2:我用"日志里有 X"代替"用户看到 Y"

Rule 56 说的是"功能 U-V",但我连续 5 轮(R22-R26)的 U-V 全是:
- grep binary 有没有某个字符串
- unit test 有没有某个函数
- 源码有没有某行注释

**没有一个是"用户打开 dialog,目录变了没有"。**

### 错误 3:我把"降级方案"当成了"修复"

fallback 写 `C:\` 到 filename —— 这不是降级方案,这是**换个方式重现原始 bug**。

**真正的降级方案应该是:什么都不做 + 明确告知用户"同步不可用,请检查 Sigma FM"。**

## 9. 对 v0.5.6 的最终建议

### 建议 1(推荐):拆分目标

把 v0.5.6 拆成两个独立决策:

| 决策 | 内容 | 风险 |
|---|---|---|
| **A. 恢复 fallback** | `should_opened_write_back` 返回 true(计划 §2.1) | 用户看到 filename 被污染 —— **这本来就是原 bug** |
| **B. 只做诊断** | `/health` 暴露 `first_push_received`,extension 显示明确警告 | 零功能变化,但诚实 |

**如果选 A,必须同时告诉用户"你会看到文件名框被写入 C:\"。**

**如果选 B,功能不变(仍然零同步),但用户至少知道为什么。**

### 建议 2:真正的治本方向

100+ 轮反复的根因是:**依赖一个已知失效的外部 API(`sigma.context.onPathChange`)**。

即使 v0.5.6 恢复了 fallback,只要 Sigma FM 的 TDZ 错误还在,**用户永远拿不到真实路径同步**。

**建议启动 v0.6 方向:sidecar 自己发现 Sigma FM 当前目录**,不依赖 extension:
- 轮询 Sigma FM 主窗口标题(FileName / 路径通常在标题或状态栏)
- 或读取 Sigma FM 的 last-opened-folder 配置
- 或让 Sigma FM 修好 TDZ 后 `onPathChange` 恢复

**这才是终点。fallback 只是止血。**
