## 2. 关键判断重申:manual deploy 是黄金基线

### 2.1 手动部署流程(`manual-install.ps1`)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File manual-install.ps1
.\focus-sync-sidecar.exe --port 37421     # 用户手动起 sidecar(spawn 模式)
```

不注册 Scheduled Task,不写 $INSTDIR\tools\ 路径,二进制在 `%APPDATA%\...\bin\focus-sync-sidecar\`。

### 2.2 Tauri installer 流程(`Sigma-File-Manager-...-setup.exe`)

```powershell
Sigma-File-Manager-2.2.2-focus-21-v0.5.5-setup.exe /S
schtasks /Query /TN KizemoFocusSync   # 验证 Scheduled Task
```

注册 Scheduled Task(`--service` 模式),二进制在 `$INSTDIR\tools\focus-sync-sidecar.exe`。

### 2.3 为什么手动部署能 sync,installer 不能?

| 维度 | manual deploy | Tauri installer |
|---|---|---|
| **binary location** | `%APPDATA%\...\bin\` | `$INSTDIR\tools\`(Program Files) |
| **launch mode** | spawn(no flag)| `--service` |
| **heartbeat** | ON(每 5s)| OFF |
| **auto-kill orphan** | 不再 | 不再(v0.3.0) |
| **port bind mode** | retry+800ms x 3 | fail-fast → exit 0 on EADDRINUSE |
| **session context** | 用户当前 console session | Scheduled Task interactive logon |
| **RunLevel** | n/a | Limited (default) |
| **registry key** | 无 | HKLM\SOFTWARE\kizemo\focus-sync\SidecarPath |

**关键差异**: 手动部署用 spawn 模式,Tauri installer 用 --service 模式。两者行为不同:

**spawn 模式**: heartbeat ON,auto-kill orphan ON(虽然 v0.3.0 删了),port bind retry 800ms x 3
**--service 模式**: heartbeat OFF,无 auto-kill,port bind fail-fast(避免多用户机器 restart-spam)

### 2.4 v0.5.5 binary 的 gate bug 是哪个 mode 触发的?

**两个 mode 都触发**。gate 是 binary 代码级别的,不影响 launch mode。

所以即使手动部署 v0.5.5 binary + extension 没有 proper TDZ,gate 也会卡死(因为 first_push_received gate 不依赖 mode)。

**但用户实测 manual deploy 可 sync**。这意味着:
- (a) 用户用的是 v0.5.4 binary(没有 gate),不是 v0.5.5
- (b) 用户手动部署 + v0.5.5 binary + extension 不 broken(extension PUSH OK → flag=true → wire succeeds)

如果是 (a),v0.5.5 binary 是真正的退步来源。修复 v0.5.5 binary = 修复退步。
如果是 (b),v0.5.5 binary 在某些 extension 状态下也能工作,gate 在某些条件下会放过。

**无论哪种情况,v0.5.6 binary 修复都正确 —— 让 gate 不要在没 extension PUSH 时把 sync 路径关掉。**
