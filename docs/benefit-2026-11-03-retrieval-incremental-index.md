# 检索改造（任务 F 增量索引）能带来什么好处

- 撰写时间：2026-11-03
- 对应计划：`docs/plan-2026-11-02-action-registry-and-incremental-index.md` §3（批次 4）
- 状态：**尚未实施**。本文写的是「按当前计划实施后能拿到什么」，其中的耗时数字来自计划文档记录的**既有基线**，不是本轮实测量。

---

## 一、先看清现状代价

当前全局搜索的索引是**每轮全量重建**：

| 项目 | 现状（已验证） |
|---|---|
| 单轮索引文档数 | 约 191 万 |
| 单轮全量重建耗时 | 12.2–12.5 min |
| 四轮基线实测 | 728,966 / 748,192 / 730,123 / 750,079 ms |

也就是说，只要你开着应用并且在扫盘，机器就要周期性地花**十几分钟**把四个盘的东西从头再数一遍、重新写一遍索引。

这笔账对使用者的体感是三层：

1. **搜不到刚出现的文件** —— 索引只在整轮跑完时才更新，中途新建、改名、挪动的东西搜不出来，只能等下一轮。
2. **周期性卡顿** —— 每轮开跑时磁盘 IO 与 CPU 被占满一片，前台操作变钝，风扇起转。
3. **耗电与磁盘磨损** —— 笔记本上是实打实的续航损失；机械盘/老 SSD 上是持续的读写压力。

---

## 二、改造要做什么

一句话：**首次全量，之后只做增量。**

- **复用已有 watcher**：仓库里 `src-tauri/src/dir_watcher.rs` 已经存在（当前用于目录监听），把它接到 tantivy writer 上，`create` / `update` / `delete` 三类事件分别对应索引的增、改、删。
- **按根分区驱动**：每块盘一个 watcher 通道，避免单通道被事件风暴打爆。
- **首次全量仍并行**：第一次建索引时四盘并行，12.5 min → 约 6.3 min。
- **降级不退化**：watcher 用不了的时候（网络盘、不支持的文件系统、权限不足）自动回落到现有全量扫描，功能照旧。

---

## 三、能带来的好处（按使用者能感知的顺序）

### 1. 搜索结果「实时」

新建一个文件、改个名字、删掉一批东西，**几秒到几十秒**就能在全局搜索里查到（或消失），不用等十几分钟。这是增量索引最直接的体感变化：搜索从「定期快照」变成「跟随现状」。

### 2. 后台不再周期性吃掉十几分钟

稳态下只有**真正发生变更**的那部分文件被处理。磁盘 IO 和 CPU 的周期性尖峰基本消失，前台操作不再被后台索引挤兑。

### 3. 续航与磁盘寿命

全量扫描是持续的顺序 + 随机读，四盘并行 12 分钟。改成增量后，笔记本的耗电和磁盘的写入量都显著下降。

### 4. 首次建索引等待时间减半

新装机、换机器、手动重建索引这类「第一次」场景：**12.5 min → 约 6.3 min**（四盘并行）。这是纯等待时间的直接缩减。

### 5. 与「目录进入慢」类问题解耦

目录读取和全量索引扫描抢的是同一块磁盘。索引不再周期性地把盘占满，目录浏览、缩略图预览这类前台读盘行为也顺带受益。

### 6. 结果正确性是有硬约束的，不是「快了就行」

计划里把验收口径写死了，必须同时满足三条：

1. 首轮 ≤ 6.3 min（四盘并行确实生效）；
2. 稳态（增量）轮 **显著低于** 12.2 min；
3. **增量更新后查询结果与全量重建一致** —— 用同一批已知路径做交叉验证。

第 3 条是关键：增量方案最大的风险是「漏事件 ⇒ 索引里留下脏数据/缺失条目」。这条判据把它钉住，做不到就不算完成。

### 7. 一套事件源，两处复用

目录刷新和索引增量共用同一个 watcher。少了向系统重复注册监听的开销，也少了一份要各自维护、各自出 bug 的实现。

### 8. 风险可控

因为保留了「watcher 不可用 ⇒ 回落全量」的降级路径，最坏情况是**退回到今天的体验**，而不是搜索直接坏掉。

## 四、边界与前提（必须写清楚）

- **尚未实施**：批次 4 还没开工，本轮交付的是「目录加载卡死」的修复，不是索引改造。上面所有收益都是**按计划实施后**的预期。
- **不是零成本**：增量索引要动 Rust 的 tantivy writer 与 watcher 接线，属计划里标注的「风险最高」批次。已知硬约束：`cargo test --lib` 链接到的代码不得触碰 `tauri::AppHandle` 或 `tauri::async_runtime::*`（否则测试二进制加载期 `STATUS_ENTRYPOINT_NOT_FOUND` 崩掉），绕法是给业务模块加 `*_blocking` 同步内核入口。
- **验收期间不能跑编译**：抢 CPU 会让计时虚高，读数作废。
- **四轮基线必须用同一条探针重跑**：`.superpowers/sdd/task3-search-accept-20261102-v2.ps1`，埋点在 `src-tauri/src/global_search/scan.rs:346`。

---

## 五、一句话

检索改造买到的是三件事：**搜得到最新的东西**、**后台不再周期性抢机器十几分钟**、**首次建索引等待时间减半**；代价是一次改了 Rust 核心的高风险工程，因此必须靠「增量结果 = 全量结果」这条判据守住正确性。
